# 问道听松

## 当前主线与接手入口

**玩家为突破境界、证道长生而修行；通过准备、秘境闯关争取机缘，在突破后获得真正不同的行动能力，途中留下自己的恩怨与牵挂。**

所有后续 session 先读 [主线总纲](docs/mainline.md)，再读 [炼气至筑基的当前规则](docs/foundation-volume.md) 和 [后续剧情方案](docs/narrative/README.md)。后续故事尚未接入，金丹及以上未实现；本地实现不等于已提交或发布。开发约束见 [AGENTS.md](AGENTS.md)。 筑基后的感情、道侣成长、旧人去向与新人登场见 [后续剧情与游戏设计](docs/narrative/04-companions-and-world.md)，目前为未实施方案。

以下版本段落是历史记录；旧数值、可选用丹、试玩冻结与未来设想不作为当前规则。当前实现应核对源码及上述专题。

当前以一个角色持续修行：本卷完成后继续原旅程，寿尽可读档或新建独立角色。主界面显示修行年月，不再提供轮回传承选择或跨角色奖励。旧版本中的轮回、世数和传承结算只作历史记录，见 [当前道途规则](docs/mainline.md#单一角色的持续道途)。

## 历史版本：归途上的药篓 v0.12.0

Vue 3 + TypeScript + Pinia + Vite 的本地单机修仙游戏。本版将炼气筑基、宗门师承、随机挑战与寻人剧情连接成一个闭环。

## 启动与验证

需要 Node.js 22.12+ 或 24.x。

```sh
npm ci
npm run dev
npm test
npm run build
```

打开终端显示的网址。dist 可部署到静态服务器；更换网址、浏览器或设备前请导出存档。

## v0.12.0 更新

- 开场用漂回的药篓、三声阵铃与护路半印串起调查、准备和营救；真相在营救与雾海旧记录中分段回收，筑基成为追查失踪修士的能力门槛。
- 归途选择留下成株，学习后续药圃可用的护根手法；或带回成株救急，获得灵草 4。人物会回应这一决定，本世不能改选，不重复发奖励。
- 营救后提供回访、修行、师门与三年之约的进度指引。成年感情线加入闭关机缘与各自道途的分歧，后续对白回应已选答案。
- 右上角“开启声音”，或菜单中的“显示与声音”可控制环境声与行动音效。首次默认关闭，开启后保存偏好，切后台暂停；无配音或完整配乐。
- 存档 v11 兼容 v1–v10 的既有迁移链，旧营救结局保留，不替玩家补选。首次保存保留 original-v10。详情见 [v12-opening.md](docs/v12-opening.md)。

## 已有玩法

- 青嶂关新增医道救草、剑道开山、识阵立约：先观察再实施，满足条件必成；选择留下药站、货车商道或定时通行的旧阵，并改变青嶂、郁青及旅亭的回应。
- 后果延续到第三卷：救草手法、商队架桥、归阵手法是实际可用的新解法。旧过关存档保留原经历，首次保存备份 original-v9。详见 [青嶂关设计](docs/v10-qingzhang.md)。
- 三卷主线与人物、地图、师门、洞府、功法、灵器、卷宗支持桌面宽屏布局；窄屏保留单列。青嶂关记路后展示分支结语，可重访故人或继续第三卷。本轮未制作桌面或移动端安装包。

- 第三卷「雾海来信」：旅亭记路后拆信 → 自选同行与探索顺序 → 旧药圃 / 废驿任一路寻证 → 商定追信或护归路 → 挑战回声阵 → 带灯归来 → 重访旧山祠。详见 [v9-mist-letter.md](docs/v9-mist-letter.md)。
- 陆迟、已相识的成年异性角色或独行，拥有不同解法与对白；共同经历记入关系，不自动定情或结婚。先走一条支线即可通关，另一条可补探。
- 失败保留证据并得到阵眼情报；研究护归法、调整准备可提高至 100%。探灵灯照见山祠隐藏灵痕，也能免费疏通药圃根脉，成长不止数值上涨。
- 新增药圃、废驿和归灯山祠三张场景图；手机单列操作，剧情在背景上，路线与准备区分开。状态版本 9，v8 进度原样保留，首次保存备份 original-v8。

## 旧档保护

v2 筑基篇存档自动接续，不重开、不重置修为或 RNG；默认补入明心善悟资质。已过去的中期互动不补发奖励，已结算自留分支补解锁孤灯丹诀。首次写入时保留 original-v2 原始备份。v3 保存全部资质、人物记忆与丹纹状态。

v1 存档读取时不修改原始数据。确认进入新篇后，以十六岁重新开篇，旧版人物和卷宗完整封存在新档的 archive 中，并在 IndexedDB 中保留 original-v1。可从界面导出旧版原档。旧版数值不直接套入新规则。

未知未来版本不会被自动降级覆盖；损坏且无可恢复备份时停止开局写入。请只在一个标签页游玩，尚无跨标签页并发锁。

## 代码结构

- src/core.ts：纯规则公开入口。
- src/chapter.ts：筑基篇状态、命令、事件投影、种子随机数、校验与迁移。
- src/legacy-v1.ts：旧版规则与校验器，保留回归覆盖和原档识别。
- src/save.ts：IndexedDB 双快照及旧档封存。
- src/App.vue：只读状态投影、命令调度与保存成功后更新界面。
- src/characters.ts：NPC 图像、台词、去向与已知经历的只读投影。
- src/legacy-v2.ts：冻结的 v2 状态校验与迁移依据。
- tests/：228 项测试，含原 120 组与新增 180 组资质/路线/结局的确定性完整重放。
- public/mountains.svg：原创矢量山景，无图片外链。

## 范围

这是筑基篇可玩原型，不是完整六境界正式版。尚未做大规模玩家平衡测试、移动真机验收、完整配乐与配音、PWA、多人、后台世界模拟或云存档。卷宗保留最近 180 条，去重保留最近 512 条命令 ID，不是永久操作日志。运行时无后端、账号或遥测。

## Windows 试玩包

`npm run package:win` 生成离线 x64 安装包和压缩包；`npm run test:desktop` 检查真实桌面运行时的重启读档与损坏回退。安装、网页存档迁移及验收边界见 [Windows 试玩版说明](docs/windows-demo.md)。


本地音乐试玩：已准备素材的机器运行 `npm run dev:music`，打开 `http://127.0.0.1:5191/` 并点击“开启声音”。五首试听曲仅在此开发入口使用，不包含在正式构建和 Windows / Steam 发行资源中。素材准备与场景安排见 [v12 体验说明](docs/v12-opening.md#本地配乐试听不进入发行包)。

## 青嶂关冒险循环（v0.13.0）

补齐坊市航图后，在青嶂关或山口行营接取“护送与旧阵”，体验山道护送、古阵寻踪与守阵交锋。每次挑战耗时和补给，失败保留小关进度；可回洞府修行、劳作和养伤。守阵交锋需筑基，首通获得护身诀并接续原有归路选择。旧档兼容，已过关者不倒退。[规则、平衡与验收](docs/v13-expedition.md)。
