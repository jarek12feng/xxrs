## 实际接通的流程

前期打坐积累 → 中期选择功法、法器及补给 → 药谷两场妖兽交锋与途中险地 → 凝露草淬脉 → 后期积累与青石遗府丹方 → 内府两场傀儡交锋与险地 → 晶髓凝元 → 圆满、筑基丹与筑基准备 → 筑基。

- 未淬脉最多 239 修为，未凝元最多 359；所有公开命令的修为奖励统一受瓶颈限制，自动队列达到瓶颈结束该修炼项。材料必须经过交锋取得；不会因一次普通委托直接晋升。
- 三种历练准备：药理消耗灵草增加气势，剑意增加伤害但多承伤，识阵强化正确辨影。守关前继承剩余气势，可用药、辨阵或带伤强闯。败退保留修为和已炼化成果；撤退不返还补给。
- 炼化方式：自行处理耗灵石 24、灵草 4，需心得 2；师门护脉耗灵石 12、贡献 4；坊市匠师耗灵石 48。并非所有玩家都必须入宗。
- 温蘅收草、季衡收伤药、郁青收行路记录，分别连接护身药、炼丹和内府筹备。委托结算一次；日常劳作和师门差事是可重复收入。现有 NPC 承接内容，本轮未另建人物关系体系。
- 榜单沿用现有分境界挑战与功法奖励，作为试招和构筑渠道，不强制排名才能筑基；未新增赛季或排行榜规则。
- 成品回春散 12 灵石，一阶灵剑/灵瓶 40 灵石；也可自行炼制。不能在秘境中购物、换装备或执行其他领域命令。
- 常驻修为和阶段缺口；三项战斗按钮直接可点，显示伤害、承伤、回气和耗草。每回合显示实际数值变化。原行路的数字键仅为快捷方式。
- 独立素材 session 制作了两张场景与两张材料图，已接入；制作原图和 QA 文件不随 public 打包。

## 证据及边界

- `npm test`：66 个文件、526 项通过。新增覆盖公开命令从建角到筑基、只打坐不能过关、三条准备路线、失败与撤退、三种炼化、购买与委托防重结算、死亡与约定抢占、非法状态、保存重放和自动队列瓶颈。
- `npm run build`、`git diff --check` 通过。Vite 仍提示主 JS chunk 超过 500 kB；本轮未以此声明性能验收。
- [18 组公开命令样本](qi-progression-art/qa/command-audit.json)：医/剑 × 三资质 × 三种子，全部到达筑基。73–80 条命令，110–124 个游戏月，额外收入 240–280、支出 240–264 灵石，余款 6–28；5–7 次劳作指令，16–21 次秘境战斗指令。参考策略已知招式规律、提前充分准备，不代表首次玩家成功率。
- 浏览器实际检查新建角色、常驻修为、100 年寿元基准、前期简化提示；通过正式命令生成的验收页点击入谷和战斗，核对气势、伤害、耗草即时变化，并查看内府素材。窄屏截图见 [战斗](qi-progression-art/qa/combat-review.png)、[新角色](qi-progression-art/qa/new-character-review.png)、[内府](qi-progression-art/qa/inner-platform-review.png)。这不是手机真机验收。
- 验收页：开发服务器 `/tools/qi-progression-preview.html`；辅助工具生成检查点而非给角色直接加资源，不写正式存档。正式游戏入口 `/`。

**尚未验收：60–90 分钟真实首玩、长期经济与寿元紧迫感。** 样本角色约 25–26 岁筑基，说明当前已形成资源和挑战门槛，但并不能证明寿元压力足够。禁止将 110–124 个游戏月或 73–80 条命令换算成人类游玩时间。下一轮应记录陌生玩家的阶段耗时、失败原因、重复劳动及阅读负担，再决定补哪些有效挑战；不以空耗年月或重复点击补时长。

旧筑基测试中依赖“较弱炼气装备”的数值夹具已调整：独立测伤害时去除护甲的零伤害下限干扰，专门构造低气势以验证失败恢复；真实公开命令路线保留新阶段挣得的功法训练和法器。单次误操作不再被断言为必败。
