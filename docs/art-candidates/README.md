# 试玩反馈后的视觉与动机改造准备

日期：2026-10-29。状态：制作原图与设计记录。用户随后授权继续接入，运行版进展见 [美术接入记录](../art-integration.md)；原 A 版试玩包不覆盖。

第一批独立素材已归档：[V1 素材清单与验收说明](v1/README.md)、[深浅底预览](v1/gallery.html)。共 34 张：角色与姿态 15 张，道具 19 张；提示词与身份参考保存在 [source-manifest.json](v1/source-manifest.json)。这是制作母版，边缘、锚点和实际尺寸辨识仍需接入前验收，不等于完成连续动画。

## 本次用户反馈（原始记录）

- “游玩的动力不足，不知道方向和目标。”
- “装备和升级时的获得体验感较少。”
- “动画人物比较丑陋，最好预先做好主角、配角、怪物等的形象，动画时拿来用。”
- 补充要求：草药、武器、装备等道具也应提前准备形象。

这是项目用户的一次真实试玩反馈，游玩时长、路线、具体节点未记录；不能推算留存率，也不能把未记录项目补成 30 分钟通过。当前结论：成长反馈和目标感仍有明显问题，不应因工程检查通过而继续扩展系统。

## 优先处理顺序

1. 动机：为当前阶段展示“想达成什么 → 为何值得 → 当前差距 → 可做行动”。目标应指向实际存在的挑战、能力和故事结果，不仅告诉玩家去哪点按钮。目标投影只读现有状态，不新增强制任务或奖励。
2. 获得感：拿到物品时展示清晰的物品形象、名称、用途和使用入口；升级展示真实前后差异及新的可达目标。装配须由玩家确认，动画在保存成功后播放，失败不能展示成功回报。
3. 视觉统一：先确定角色/道具基准，再做姿态与效果，替换现有几何拼接人物。不会通过延长不可跳过的动画制造获得感。

## 风格与制作规则

- 延续现有国风水墨设色、青绿与暖金配色；人物比例自然，脸部可读，战斗角色与对话肖像是同一身份。当前陆迟肖像是身份参考，不直接推翻重画。
- 角色和道具以独立透明底原图交付。角色统一脚底锚点、朝向和画布边距；同角色后续姿态从已确认基准派生，避免身份漂移。武器/头发等不为翻转朝向而错误换手。
- 道具优先检查 48/64px 的轮廓辨识，不以光晕遮住本体。品质/精炼状态不能只靠颜色区分；不得增加不存在的稀有度、掉率或随机属性。
- 基准图和生产素材分开。风格预览板仅用于比较方向，不能直接切图当最终素材、骨骼分层或连续动画帧。
- 动画先用清晰姿态切换、轻位移与独立剑气/药光/阵核效果；不把整张立绘剧烈拉伸来模拟肢体动作。需要复杂动作时补相同身份的专用姿态。
- 原图、提示词、生成方式、身份参考和用途应留档；压缩版供运行加载。角色只加载当前场景所需，固定尺寸避免布局跳动，后台暂停，减少动态效果时使用静态画面。

## 后续接入结构（尚未实施）

- 独立素材清单管理角色 ID、姿态、物品 ID、图像路径、锚点和显示尺寸；领域状态不保存图片 URL。
- 角色显示组件处理加载和姿态；表现层动作脚本处理时序；游戏核心仅负责结算，动画不得扣资源或改变种子。
- 同一道具资源由背包、商店、装配界面、奖励回执共同引用。功法效果/装备收益仍读取规则投影，不能由美术配置复制一套数值。
- `PracticeStage.vue`、`expedition/BattleStage.vue` 和擂台使用统一角色资源，不继续各自拼人；`App.vue` 只负责必要接线。

## 验收

- 玩家无需展开攻略即可说清当前目标、达成价值和一个可执行动作；已完成目标及时退出。
- 首件功法/灵器获得后，玩家能认出物品并自行装配，指出一次实际收益；指标沿用商业化前计划，不能只以截图好看验收。
- 角色在对话、修行和战斗中的脸、发型、服装保持一致；缩小到实际游戏显示尺寸仍可辨认，透明边缘无白框、脚底不漂移。
- 灵草、三类丹药、两类灵器和六种功法载体在实际尺寸下可区分，数量/用途/阶段显示准确。
- 领取、装备、升级演出可跳过，跳过/刷新不重复发奖励，保存失败不播成功；低动态模式可完整理解结果。
- 接入运行版前另立新版本并通过规则测试、构建、实际界面和素材加载验证；A 版试玩包与原始样本保留。

## 功法载体补充

用户明确功法既可用玉简，也可用书籍。当前素材采用两种载体，玉简通过玉质、长条轮廓和刻纹与书册区分；载体不改变任何规则、稀有度、获取方式或装配条件。
