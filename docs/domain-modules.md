# 功法、成长、日程、丹药、收支与剧情交互模块

2026-11-04：按用户确认的顺序接入现有流程。此轮是规则与协议提炼，不增加境界、物品、技能或剧情；不增加存档字段、不更改装备和成长数值。共享工作区的旅行、战斗改动保留，各自验证范围见相应记录。

## 1. 功法与技艺：src/techniques

`catalog.ts` 拥有六本基础功法定义；`index.ts` 暴露：

- `techniqueChangeError` / `applyTechnique`：学习、装配、研修的条件与执行。坊市学习扣灵石 20，心得只作门槛；研修扣灵石 12、灵草 2。事件锁与存档仍由命令协调者负责。
- `grantTechnique`：剧情赠书，不收学费，重复获得返回 false；剧情自己决定是否折为灵石。
- `canGather` / `canTrain`：按已学功法开放采药与练剑，不再散落在世界入口。
- `techniqueActivityEffect` / `techniqueCultivationBonus`：采药、练剑、劳作、凝神与吐纳的功法贡献。
- `mainTraining` / `supportTraining`、`techniquePower`、`techniqueCombatProfile`：基础攻守与转修生效状态。
- `methodQuote`：澄息篇、抱元凝神录的首次参悟/转修工期和局部条件；是否取得秘籍、是否位于安全处由剧情提供事实。

已接入 world、growth、learning、修炼计算、战斗状态适配，以及拍卖、宗门、同行、炼气/筑基剧情的赠书路径。兼容导出保留在旧位置。战斗引擎仍负责招式时序、正确应对、阵核、治疗及致死规则；本轮没有把所有战斗公式搬进功法目录。

## 2. 修炼与境界：src/progression

- `cultivation.ts` 拥有阶段、寿元效率、逐月修炼、整数零头累计、预估和活动附带修炼。旧 `src/cultivation.ts` 改为兼容导出。
- `caps.ts` 集中炼气、筑基、金丹瓶颈上限；原章节状态模块保留导出，校验和 UI 共用同一规则。
- `breakthrough.ts` 集中筑基成功结果、成功率分项、失败损失，以及凝丹条件、成功率和寿元变化。

保留：筑基失败七成/护脉九成修为的整数取整，护脉消耗、受伤上限及既有减寿；凝丹成功在现有寿元上加 300 年。随机种子仍由原命令抽取，推进时间与剧情中断仍先于消耗丹药和发放突破结果。门派比试、秘境获得材料、贯流等事实继续归各章所有；不补发旧剧情奖励。

## 3. 时间与日程：src/timeline

`advanceMonths(input, months, { tick, interrupt })` 逐月调用既有月转换，返回 state、elapsed、remaining、stopped 和 reason。调用者提供中断策略。已用于炉房、拍卖、凝丹筹备、外海非旅行筹备及诸宗会非旅行筹备；旅行引擎的续程存档与路线结算继续由旅行模块拥有。

- 已经阻塞时不调用 tick；零月操作由其命令自行校验。
- 每月结算后检查中断，最后一月触发事件仍视为中断，不能因 remaining 为零而发放成果。
- tick 必须代表原有一次月转换；该接口本身不读取系统时间、不创造月收入、不写存档。
- 各活动的中断、费用与成果策略保留。例如原炉房检查寿尽/来信，拍卖还检查社交事件；不能用一个过宽的全局条件改变所有活动。

`nextDeadline`、`dueDeadlines`、`limitBySchedule` 支持多个已知日程。外海的 `calendar.ts` 提供诸宗会 deadline；闭关预估和会期触发共享它。早期家书、旧约和其他人物日程仍由既有章节时钟处理，本轮没有将全部剧情日历重新建档。

## 4. 丹药使用：src/medicines

在既有七类目录基础上增加 `quoteMedicineUse`、`dailyMedicineQuote`、`applyDailyMedicine`。

- 回春散日常疗伤最多 2；清心丹神识最多 +2、上限 12、间隔三月；只有清心丹写冷却月份。
- 护脉丹在战间通行提供回气 26，实际气势上限与伤势影响由通行规则统一裁定。
- 筑基丹、凝丹丹药分别限制在对应突破场景；每次尝试消耗一枚，不可当普通疗伤药。
- 失败报价不消耗库存，不改冷却，不产生药效；效果是只读数值，实际使用走原命令。

日常服药、炼气通行和两个大境界突破均已接入。突破是否准备充分、战间能否通行等仍由相应剧情/成长规则校验。解毒和修炼丹药分类仍为空，不把目录项当已实现玩法。

## 5. 行动成本与收益：src/economy

`quoteSettlement` 返回统一资源行（before、cost、reward、after）；`settleResources` 在命令草稿上原子更新；`claimResources` 使用调用者已有的领取事实防止重复领取。

- 先检查全部资源再写入；拒绝未知资源、负数、小数、余额不足和超过存档上限。
- 本次奖励不能垫付本次入场成本。
- 支持灵石、灵草、玄铁料、护脉丹、筑基丹、回春散、清心丹；其他剧情资源仍由原模块拥有。
- 不另建奖励账本；命令 seen 和章节领取事实继续负责幂等性。

已接入炉房、宝物委托/精炼/竞拍、凝丹、外海、诸宗会、功法学费/研修及初始重复谢礼。不是全仓库全部资源写入已经迁移；其他剧情奖惩仍通过既有命令执行。

## 6. 剧情交互协议：src/story-interactions

`projectInteractions` 将剧情选项与权威报价组合成统一的 id、label、action、available、error、months、cost、quote；`inspectInteraction` 在执行前重新验证；`selectInteraction` 支持根据当前选项集合重新解析选择，拒绝已经消失或条件变化的选项。

当前动作 ID 针对现有扁平命令参数生成，不使用中文标签作为身份。凝丹、外海、诸宗会的选项列表已接入；三个命令入口也通过相同报价协议检查。界面仍只发出命令，不能凭缓存的 available 执行行为。

剧情台词、人物立场、场景热点、阶段转换和后续去向留在各章；结果沿用已保存状态驱动的 action-feedback / journey-feedback。此次不新增通用剧情脚本语言，也不声称全部章节已改写为同一种状态机。

## 依赖和状态归属

- 新规则模块全部是纯 TypeScript；不导入 Vue、Pinia、DOM、浏览器存储或真实时钟。
- techniques 只向 economy 提交窄资源视图；progression 的章节结构依赖是类型导入，章节事实不会由预估写回。
- 只读报价、预估、选项投影不消费种子、不发奖励、不改原状态。执行接口仅操作命令拥有的草稿。
- 存档字段继续归原领域，未新增存档版本。旧公开路径保留兼容导出，调用方可逐步改用模块入口。
- 不以本轮命令级重构替代正常 UI 从零连续试玩、Windows 或 Steam 验收。
