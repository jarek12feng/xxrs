# 装备模块抽离（2026-11-04）

本轮将已有装备规则集中到 `src/equipment/index.ts` 对外接口。保持已有装备数值、两个装配位和温养宝物生效方式；不增加随机词条、耐久、多实例背包或新的装备槽。

## 职责和依赖

- `catalog.ts`：灵剑、灵瓶、三种辅器及两件温养宝物的定义；用途分类、器物形态、层次、装配位、精炼上限、境界条件、基础数值；器纹与辅器的招式条件和分阶数值。
- `context.ts`：与现有存档兼容的最小结构类型，以及装备能力查询。没有 world、Vue、浏览器或随机源依赖。
- `effects.ts`：基础攻防、招式效果、不同探索情景的把握、失败伤势减免和筑基修炼贡献。效果返回数值与逐来源贡献。
- `operations.ts`：装备局部条件、取得、精炼、刻纹、装卸与纯预览。
- `index.ts`：外部调用入口；其余文件属于模块内部。

现有状态仍在 `journey.relics/equipped`、`workshop.temper`、`treasures.owned/equipped`，剧情宝物仍由 `outerSea`、`conclave` 保存获得与温养事实。模块通过结构类型读取这些字段，不导入完整 State。装备本轮没有新增存档字段、没有修改版本或迁移；共享工作区同时进行的旅行版本升级属于另一个任务。

## 对外能力

| 接口 | 契约 |
| --- | --- |
| `getEquipment(id)` | 返回用途分类、器物形态、层次、槽位及定义；品阶与精炼阶数分开 |
| `listEquipment(category?)` | 按攻击、防御、速度查询；支持一件装备兼具多个用途 |
| `inspectEquipment(context, id)` | 返回持有阶数、生效情况、定义及驾驭限制；剧情温养宝物说明不占装配位 |
| `equipmentChangeError(context, change)` | 检查局部条件，返回空串或原因；不扣材料、不变状态 |
| `applyEquipmentChange(draft, change)` | 在命令拥有的草稿上改装备字段；非法变更返回 error 且不修改；合法重复装配报告已装配 |
| `previewEquipment(context, changes, situation?)` | 复制需要变化的装备分支并按相同规则计算；返回 next、before、after、error；任一失败则返回原状态，不暴露部分完成结果 |
| `evaluateEquipment(context, situation)` | 返回 damage、armor、incoming、chance、injuryReduction 及 sources |
| `hasEquippedRelic(context, rank?, id?)` | 查询实际装配的主器能力，支持指定剧情器物 |
| `equipmentCultivationBonus(context)` | 仅筑基且已装配二阶主器时贡献 1；兼容没有装备的第一卷状态 |

`getEquipment` 的 ID 是编译期约束；外部不可信输入须先经过命令与存档校验。配置只读使用。状态写入只允许规则命令调用，UI 不可直接调用修改接口。

**局部条件不等于全局行动许可。** 装备模块不认识章节事件、旅行、拍卖进行状态、死亡锁、资源余额或月份；这些由原命令协调者校验。炉房、拍卖先取得完整报价并推进既有时间流程，中断时不发物品；通过后在同一个命令草稿结算费用与装备。主器既有重复装配命令的回执行为保留。预览同样检查装备局部条件，但不支付成本、不执行全局行动、不写存档、不消耗种子。

## 情景与数值对照

| 情景 | 保留的规则 |
| --- | --- |
| 基础攻防 | 灵剑一/二阶伤害 2/5；灵瓶一/二阶护体 1/3 |
| 锐锋纹 | 反击伤害 +3、承伤 +1 |
| 照隙纹 | 正确辨影 +4 伤害，反击 -1 伤害 |
| 镇守纹 | 守势伤害 -1、承伤 -3 |
| 流转纹 | 正确辨影伤害 +1、承伤 -2，反击承伤 +1 |
| 镇岳钟 | 守势承伤 -2/-3；反击伤害 -1 |
| 缚风索 | 反击承伤 -2/-3、伤害 -1 |
| 照隙镜 | 正确辨影伤害 +2/+3；辨错无效 |
| 温养 | 镇潮印伤害 +4、护体 +3；定神珠护体 +5；不占主器/辅器槽 |
| 寻亲遭遇 | 一/二阶基础把握 10/32；对应敌人额外 +8；灵瓶失败少受 1 伤势 |
| 山口器物路线 | 每阶 +10；灵瓶额外 +10 |
| 雾海 | 对应阵势每阶 +6；其他每阶 +3 |

`base` 默认仅主器，`includeAttuned: true` 明确包括温养宝物；避免早期试剑榜等旧调用被无意改变。`turn` 只返回器纹与辅器修正，不能再次加入基础伤害。`incoming` 是承伤增量、`armor` 是基础减伤，符号含义不同。战斗模块继续负责招式、境界压制、最低伤害、治疗和致死顺序。

## 用户追加确认：装备与丹药用途分类

装备的 `categories` 是攻击（attack）、防御（defense）、速度（speed）；`shape` 则是剑、瓶、钟等器物形态。槽位、灵器/法宝层次、精炼阶数独立表达。听松灵剑与照隙镜归攻击，归元灵瓶、镇岳钟、缚风索及定神珠归防御；镇潮印同时归攻击和防御。当前没有速度装备，速度查询返回空列表，没有给已有物品加速度，也没有更改旅行或先手规则。

新增 `src/medicines/index.ts` 只读目录接口：`getMedicine`、`listMedicines(category?)`、`medicineCategoryLabel` 与 `medicineCategories`。按用户确认提供疗伤、回气、修炼、突破、解毒、神识、护脉七类；一枚丹药可有多个用途。回春散归疗伤、清心丹归神识、护脉丹归回气和护脉、筑基丹与已有凝丹丹药归突破。修炼、解毒当前为空，不列尚未开放的化婴丹为可用物品。

原有 `medicines` 两种常备药配置改由目录统一提供，炉房复用筑基丹与护脉丹定义。服药、冷却、配方费用与突破消耗仍由既有规则拥有，本轮不宣称完成整个丹药规则抽离。凝丹丹药仅在目录归类，仍由凝丹剧情展示与使用，没有增加普通炉房购买入口。

储物袋详情、炉房卡片、辅器卡片显示统一用途标签；用途分类本身不改变状态。新增 `tests/item-categories.test.ts` 三项测试覆盖多用途筛选、空分类及实际 Vue 界面的用途标签和浏览无状态修改。
