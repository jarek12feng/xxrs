## 桌面崩溃定位与边界

原复现命令 `node tools/test-desktop.cjs` 曾在 read 阶段断言完成后以 SIGSEGV 退出，属于失败，不能仅看 passed 输出。

两份本机崩溃报告在 faultingThread 的调用栈指向 `/usr/local/.OCular/dylib/libSC.dylib` 中 `ossl_sa_get` / `ossl_method_store_add`，并非游戏 JS；原样复跑亦曾完整通过。

最小复现：

```sh
node_modules/.bin/electron tools/desktop-exit-probe.cjs
```

仅创建隐藏空白窗口、载入 data URL 后正常 app.quit，不含游戏、协议、存档或探针。连续执行第 6 次出现 SIGSEGV（前 5 次退出码 0）。因此无法把它归因于游戏存档；证据支持本机外部动态库/运行环境的问题。没有禁用、卸载或绕过该软件，没有把 app.quit 换成强退，也没有将 SIGSEGV 当成功。

烟测现区分 assertionsPassed 与父进程确认的 assertionsAndProcessExitPassed，新增 `--repeat 1..20`，任何一轮失败即停止，不自动重试到绿。代码仍保持严格退出码门槛。当前构建顺序复测三轮、共十二进程全部正常完成；这不消除空白窗口已有的间歇性复现，也不代表 Windows 已通过。

开发时一次同时重建 dist 与启动桌面检查导致加载失败，此结果作废；此后明确按构建完成 → 桌面测试顺序执行。禁止把并行重建中的产物用于正式烟测。

Windows 自动流程已落入 `.github/workflows/windows-demo.yml`，包含 npm test、桌面存储检查、构建、静默安装、实际 EXE 启动和正常关闭。仅本地文件准备，尚未推送或执行。真实 Windows 安装、缩放、声音及更新验收仍是公开分发前的外部设备待办。
