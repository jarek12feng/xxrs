# 战斗模块深化与剧情接入

2026-11-05。基于已有纯战斗引擎深化，不重写数值，不新增装备或剧情奖励，不调整存档格式。

## 模块职责与接口

- `src/combat/index.ts`：纯模块公共入口。开始战斗用 `startBattle`；只读报价用 `previewAction`；执行用 `executeBattleAction`。旧擂台概率玩法及一次性遭遇继续使用独立的 `preview/resolveArenaAction`、`preview/resolveEncounter`，不强改成轮流三招玩法。
- `action.ts`：完整回合交易。检查存量与终局，调用当前状态的纯报价一次，拒绝不足的草药，统一执行回合，返回下一状态、剩余草药、胜负和实际战报数据。不会修改输入、推进年月、写存档或给奖励；只有命令拥有者提交结果。不能传入缓存的UI报价代替重新计算。
- `engine.ts`：有序计算流程，保留基础、主法、阵核、装备、局部调整、境界压制、伤害下限、回春和尾部环境压力的原顺序。增加机制应在相应计算阶段实现，不能在Vue里加减伤害。
- `mechanics/array.ts`：阵核闭合、暴露、蓄势与探阵内部实现。场景通过既有配置声明启用；此文件不导出到公共入口，调用方不依赖内部文件路径。
- `turn.ts`：回合状态机，区分击倒免反击与同时结算，统一回合上限、胜负和实际伤害。
- `game.ts`：游戏状态适配器，把功法、装备、神识、境界压制转成纯战斗输入。装备仍由独立 equipment 模块计算，不能在剧情复制法宝规则。
- 场景保留：当前敌人/阶段、准备与剧情条件、上一招记录、地方性附加规则、时间/报名费、胜败/撤退后果、奖励和存档命令幂等。没有把全世界状态交给纯引擎，也没有运行时插件注册或未使用的通用框架。

## 新场景如何接入

1. 用内容配置给出敌人气势、攻击、来势和上限；准备条件和报名成本留在剧情命令。
2. 定义一个纯 `sceneExchange(state, move)` 适配函数，调用 `tacticalPreview`，通过 `CombatAdjustment` 注入局部变化；UI也只读这个函数。
3. 执行命令调用 `executeBattleAction(duel, state.herbs, policy, () => sceneExchange(state, move))`。用结果的 `battle`、`remainingHerbs` 提交状态；用 `exchange` 写战报；用 `outcome` 触发一次剧情后果。
4. 新法宝只接 equipment 的公共计算与来源；普通场景自动复用。独特机制仍要验证该场景的配置/失败恢复与奖励，不以引擎通过代替全场景验收。
