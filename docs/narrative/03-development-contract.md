# 剧情接入与验收契约

状态：后续开发依据，未实施。以[总纲](README.md)的已实现事实和本次对话冻结要求为边界。这里的节点、状态、奖励与演出均为设计提案，不构成已经存在的 API、存档字段或资源。

## 1. 范围与先后次序

冻结期只评审文档、记录问题，不把本文对白、任务、数值或演出接入运行版本。获得明确的后续开发授权后，也不默认一次实现全部故事。

推荐首个闭环为 NAR-01：收讣帖 → 调查渡口 → 确认姐姐生还 → 取证与营救 → 处理渡口 → 回坊市看结果。先交付这一章的完整闭环，再考虑爱情线；家族与宗门是后备中篇。轻支线可在内容排期允许时用于舒缓，不作为主章必经步骤。

NAR-01 首稿的阅读加操作时长预算为约二十五至四十分钟，爱情线各十至二十分钟，家族与宗门各二十至三十五分钟，轻支线三至五分钟。**这些是创作预算，不是已测时长或商业化指标。** 试玩若发现停留过久，应删重复解释、合并调查操作，而非加速字幕或隐藏跳过按钮。

现有前三十分钟不因这些故事被延长。新章可在雾海归来、已有战斗与资源循环建立后触发；若当前实现没有无名渡地标，未来须单独评审其落点，不默认开放更高境界区域。

## 2. 内容节点与入口

下表 ID 是文档索引，不要求照搬为代码枚举。

| 节点 | 进入时必须成立 | 本节点可以给出的事实 | 离开条件 |
| --- | --- | --- | --- |
| NAR-01-A 讣帖 | 认识郁青；到达适合雾海后续的进度 | 纸、针孔、邮路；只能提出生死疑问 | 核对邮路，选择接案或暂缓 |
| NAR-01-B 渡口 | 已接案；具备可达路径 | 初期收留事实、记录矛盾 | 取得下井或侧院调查入口 |
| NAR-01-C 沉井 | 事先展示危险及返回方式 | 离渡申请与已故通知冲突 | 带回副簿，或失败后走补证入口 |
| NAR-01-D 重逢 | 已取得侧院接应线索；不要求全收藏 | 姐姐生还、隐名经过、各人意愿 | 至少了解一项可选处理方案 |
| NAR-01-E 对质 | 已明确选择推进；救援方案可执行 | 仅对已取得证据支持的行为进行指认 | 完成救援或进入有出口的补救阶段 |
| NAR-01-F 结案 | 人员与证据结果已确定 | 本案事实、处理结果与未证事项 | 一次性结算，开放回访 |
| NAR-02S / 02Y | 已认识相应人物；职业事件独立于恋爱资格 | 共同工作、分歧、交接 | 工作结案与亲密选择分别记录 |
| NAR-03 | 独立委托或无名渡供货线索 | 只说明存在供货关系，不直接定罪 | 核账与交接完成 |
| NAR-04 | 能接触丹堂与剑院；不要求选定其中一方 | 碑文与实物矛盾 | 分责、更正与复核安排完成 |
| NAR-05 | 能到达对应驿站 | 眼前生活事件 | 修补、煮面、回访变化 |

“雾海后续进度”须在落地前映射到实际领域条件并写用例，不能只凭 UI 显示的章节名判断。姐姐的既有交接簿证据不是寻人入口的唯一门槛；未查者以有限知识进入，未来补查时再更新结论。

爱情段只在沿用现有配对资格、玩家年满十八岁、明确表达恋爱意愿时出现。朋友支线不需要新增一套配对规则；未满足恋爱条件时保留职业事件，隐藏恋爱选项，不诱导玩家用赠礼越过年龄限制。

## 3. 世界真相、玩家证据、人物态度分开

世界中发生过某事，不代表玩家已知道；玩家知道，也不代表每个 NPC 已获告知。开发时至少在概念上区分：

1. **章节进度**：未接、调查、已见本人、准备对质、已处理、回访。只保留真正影响流程的阶段。
2. **取得的证据**：按稳定内容 ID 记录，证据展示从配置派生，不把完整对白塞进存档。
3. **告知与同意**：谁同意公开身份、谁已得知姐姐生还；不是单一“全员知情”开关。
4. **处理结果**：优先方案、人员接续、记录保全、补救是否完成。不要仅存一个“好结局”数字。
5. **结算与回访**：奖励是否已给、回访是否看过，防止重复进入刷资源。

这些是设计概念，具体字段应在实现前按现有状态结构收敛。若事实可从既有状态可靠派生，不重复存；若一个决定未来确实影响世界，必须持久化，不依赖组件局部变量或日志文字。

例：得到邮递存根只能解锁“讣帖由渡口交寄”。不能顺带解锁“姐姐仍活着”“祝庭挪用救济”。见到姐姐后可以确认生还，但未取得废驿交接簿时，只能说“她向你说明当年随队救治”，不能说“你早已查明”。

证据组合由纯规则判定，再给 UI 可展示的结论。按钮可用性、任务提示、NPC 对话和结案页使用同一只读投影，避免“目标让玩家找郁青，却没有可点击认识入口”一类断路。

## 4. 有限分支，真实后果

主干保持六场；支线影响援手、可用证据、对白与尾声，不为每个旧选择复制一整章。

| 既有状态或新选择 | 必须回应 | 不允许推断 |
| --- | --- | --- |
| 留成株 / 取成株 | 对应护根或药材救急的经验；旧行为都救过人 | 取药者贪婪、不配得到医道帮助 |
| 青嶂医 / 剑 / 阵 | 药站接应 / 商队运送 / 按约通行等实际优势 | 剑路无脑粗暴、某路线独占真相 |
| 青嶂 legacy / 未选 | 可使用本地公共接应，不描写玩家当年具体修路方式 | 随机补一条历史路线 |
| 雾海石园 / 废驿 | 按证据区分已知线索，提供补查入口 | 石园玩家自动知道全部交接簿内容 |
| 陆迟父亲已寻回 | 承认亲笔信和已知生还 | 重新推送其死亡悬念 |
| 姐姐身份未获公开同意 | 脱敏提交、单独确认；可延期公开 | 玩家选一个按钮即可替所有幸存者同意 |
| 拒绝恋爱 / 暂缓 | 继续职业和案件路线；不扣主线奖励 | 拒绝意味着背叛或该 NPC 必须死亡 |
| 证据损坏 | 结论降级，明确可走的补证通路 | 销毁后仍引用原件全文作确定结论 |

每条主结局至少实现一个可以回访的世界变化与一句对应人物反应。暂时无法制作独立场景时，可用已有场景中的交互物和角色行动呈现，但不能只换结案标题就宣称分支完成。

## 5. 失败、资源与奖励

- 复用已有成长与战斗规则；本轮文档不指定新增境界、属性、战力门槛或奖励数值。
- 调查的关键事实不靠无限随机检定。较强构筑可省救援成本或多保全一份材料，较弱角色有准备、撤退或替代调查路径。
- 危险进入前显示可理解的准备建议和可能损失。阅读、翻页、切界面不推进隐形时间；只有明确的领域行动推进剧情。
- 对质准备不足时可以回去修行。若已经进入危机，退出、败退和读档恢复必须有定义；不得靠刷关闭界面重置代价。
- 失败损耗遵守现有资源与伤势规则，资源不为负。至少保留一条无需稀缺消耗品的恢复通路，避免“没钱疗伤所以不能挣钱”的死锁。
- 核心奖励按章节一次结算。公共追责、先护送和破禁都获得相当的基础成长回报，额外侧重可有差异，但不得让保护隐私必然损失唯一关键功法。
- 剧情奖励优先采用已有物品、现有修行资源、角色见闻与场景变化；新物品或新功法另行评审。灵兽轻支线不承担冲击数值平衡的大奖。
- NPC 的爱情不列入奖励表。告白是明确的双方回应，友谊不是低配结局。

## 6. 代码与存档接入原则

遵循[实现边界](../implementation.md)。未来实现时按职责拆分：剧情配置描述节点和内容，纯规则判定证据与阶段，命令执行变更和结算，只读投影生成可见选项，UI 播放表现，存储层处理校验迁移。不要把整章逻辑放进 `core.ts`、`world.ts` 或 `App.vue`，也不为六场戏先造一套通用脚本语言。

随机演出不能改变规则结果；规则若涉及随机，沿用状态种子。相同种子和同一命令序列应产生相同结果。演出重播、跳过与组件卸载均不得再次发奖或推进两次。

旧存档没有本章状态，表示“未参与”，不表示“忘记过往”或“默认选过好路线”。迁移须保留已有药路选择、雾海进度、父亲生还证据与关系承诺；不凭空让成年旧玩家自动恋爱。若引入持久字段，按实际存档约束更新版本、校验与迁移；未知格式不能覆盖。提交前检查加载、保存、刷新和继续游玩的完整链路。

对话列表不在每帧遍历全世界状态或序列化整个存档；证据投影按依赖计算。场景画面与音轨按需加载，离场释放计时器、监听器与失效播放。表现不能阻断领域命令的幂等保护。

## 7. 表现清单与资源缺口

以下是制作需求，**不是现有素材已具备的声明**。优先复用已授权且气质合适的资源，具体音乐文件须试听、核对曲目与发行权限后填写，不凭文件名假定版权或情绪。

| 场面 | 最少要让玩家看见 / 听见 | 可以省略 | 不可省略 |
| --- | --- | --- | --- |
| 讣帖 | 一张可翻看的纸、针孔细节；坊市声渐低 | 新开场过场动画 | 玩家知道自己看到了什么，而非突然收到结论 |
| 无名渡 | 药布、补船、排队领药的日常；水与木板声 | 大量可交谈路人 | 救助与控制并存的环境证据 |
| 沉井战斗 | 水位、出口、守卫目标可辨；施法与命中反馈 | 新战斗系统 | 目标、结果、失败返回口清楚 |
| 姐弟重逢 | 先换药后相认的动作顺序；短暂安静 | 必须落泪的特写 | 给人物说完与停顿的空间 |
| 钟楼对质 | 门禁启动、守卫移向账柜；紧张音乐 | 多阶段首领变身 | 威胁与玩家可处理目标对应 |
| 刻板 / 守灯 | 手边共同工作、修改前后实物 | 独立约会小游戏 | 两位伴侣的动作与语言不能换名复用 |
| 结案回访 | 地图、渡牌、凭单或值班记录改变 | 大段世界旁白 | 玩家此前决定真的改变了某件事 |

声音关闭必须覆盖背景音乐、环境声和效果声；对话压低音乐，切场渐变，循环无明显断口。用户关闭声音后，不因进入剧情或跳过演出自动恢复。字幕、静音、减少动态效果下仍能读懂证据；针孔不能仅靠极低对比或音效提示辨认。

对白初稿允许文学性，但最终进游戏前需按屏幕阅读拆段、演练自然口吻；冻结期间不直接替换现有文案。

## 8. 后续验收用例

### 自动化与规则检查（实现后执行）

| 场景 | 必须验证的结果 |
| --- | --- |
| 固定种子同命令序列 | 阶段、证据、奖励和人物后果一致 |
| 未取得交接簿，先见姐姐 | 台词不引用尚未拿到的档案；后续补查不重复重逢奖励 |
| 三条青嶂路线、legacy 与未选状态 | 对应帮助真实可用；不出现虚构旧经历；均有结案路径 |
| 陆迟父亲已寻回旧档 | 不重启生死悬念、不抹去既有信件 |
| 对质中途保存、刷新、跳过、重复点击 | 不双重结算；危机状态可恢复；无空选项软锁 |
| 证据损坏或战斗失败 | 至少一条可达补救路线，不引用损坏且未留副本的内容 |
| 成年 / 未成年、单身 / 定情、拒绝爱情 | 年龄与同意门槛正确；案件和职业奖励不被恋爱状态阻断 |
| 未公开同意与已公开同意的混合证人 | 分别脱敏和展示，不用一个全局开关公开所有人 |
| 旧档无新章字段 / 未知格式 | 按迁移策略进入未参与状态，或保留原档并报告不可识别 |
| 待处理事件、死亡、飞升、资源不足 | 沿用核心禁止推进条件；资源不为负 |
| 静音、切场、离开组件 | 不漏播背景音乐，不残留定时器或重复监听 |

新增规则写对应测试。正式实现提交前执行项目要求的 `npm test`、`npm run build` 和 `git diff --check`。通过这些只能证明相应实现检查通过，不能宣称故事已经有吸引力。

### 人工试玩与剧情评审

先让玩家自由复述，再问具体问题，不在问题里暗示正确答案：

- “你觉得渡口发生了什么？哪些部分已经确定，哪些还只是怀疑？”检查证据与推测有没有混淆。
- “你决定先做哪件事？当时预计会有什么代价？”检查选择是否可理解，是否所有人都认为某选项全面占优。
- “谁做过一件你不赞成、但能理解的事？”若只能回答反派很坏，说明人物动机尚未呈现；不能强求同情反派。
- “你记得沈听澜或尹照川想完成什么吗？”检查玩家是否只记得他们是恋爱对象。
- “哪一段你想快进？哪一段你愿意停一会儿？”记录实际停顿、跳过和卡点，不以文字总量代替沉浸。
- “结案后你想再见谁？为什么？”允许回答没人，不把问卷设计成引导好评。

记录版本、存档起点、路线、实际用时、原话与卡点。先修断路、信息不公平、无法理解的选择，再讨论新增内容。样本有限时明确写样本数和局限，不把一位玩家的喜欢写成 Steam 销量判断。

## 9. 开发前仍需决策的事项

1. 核定郁晚舟及新人物姓名、无名渡位置和与既有地图的衔接，避免同名或地理矛盾。
2. 把入口条件与已有进度逐项映射；核对所有已完成雾海的旧档路径，不只验证新建人物。
3. 给祝庭、阙氏与旧年雪灾分别建立可复核的文书日期和数量表；先验证推理，再做精美案卷。
4. 确认护送、封存移交与独立复核由谁执行、何处反馈。不得用一句“交给官府”引入未设定的万能机构；首个切片可采用现有药队与丹堂、剑院的分工见证，并说明利益冲突如何回避。
5. 为每种处理方式列出实际保全与损失，检查不存在显然更便宜且全方位更好的漏写办法。若找到合理优解，应修剧情，不把玩家的聪明强行封死。
6. 清点画面、动作、音频与文本量，再据产能裁剪；保留结案和回访，不先裁掉后果只留悬念。

以上决策未完成时，文档仍是可评审方案，不标记为“开发已就绪”或“剧情已接入”。
