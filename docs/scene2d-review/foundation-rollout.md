# 筑基既有剧情的场景入口改造

日期：2026-11-03。本轮只改表现和交互入口，不新增剧情、规则、奖励、存档字段或月份成本。以 PC 场景视野为主；共享舞台实现见 `src/scene2d/NarrativeStage.vue`。

## 已接入范围

- `FoundationPanel.vue`：听松行前居、无名渡/沉井/传承内室、药庄、雪线、旅亭、古道及既有营救后地点；同行关系与筑基试剑榜也使用同一舞台。现场人物或器物展开当地行动，行囊展开整备，道路展开旅行。照玄之约只在规则投影可见时出现，打开后独立显示照玄场景，不把两个完整场景上下堆叠。
- `CompanionshipPanel.vue`：相约、合力开路、路图/灯谱争议、试行、回访。人物交流与险段操作分开，已有透明全身同行素材在确认同行已开始时进入画面；功法入口不发出剧情命令。
- `SecretPactPanel.vue`：约定、入府准备、分取/毁约、争宝与退出、寄补给与了结旧怨。石台/来信、阵图与退路、府门三个对象分别承担对应操作。贺崇的真实气势、攻势、败退与退路成本保留；争宝仍进入既有正式战斗。
- `SectContestScene.vue`：口信/赴约、逐场内比、台下整备、成绩补给与离场。所有现有合法动作保留，明确弃权和退出后果；不新增常驻大会入口。

## 交互与状态约束

初入场景只显示地点、当前目标和对象入口，不直接展开全部按钮。点击对象是组件局部状态，不改变领域状态。地点/场景阶段切换后收起旧操作层。战斗时直接显示所有出招、撤退、对手信息和本合预览，无需先选热点。

动作仍发送原有 `Intent`，锁定与报价仍用原规则。父层提供成功保存后的状态后，场景才变化。最近结果首句作为短回执，详细背景/结果留在见闻或对象内。同行的消耗提示与禁用原因分开显示，避免禁用原因覆盖真实消耗。

试剑榜结算后保留真实首胜灵石、修行和“奖励已入袋”状态，切换组别再回到筑基组仍可看见，不依赖刚才的结果弹窗。

本轮没有把相识、营救或结契改成新前置，也没有改变不恋爱仍参与苏婉宁筑基主线的规则。尚未发生或不在场的人物不由舞台补造；部分人物素材仅作为点击后的对话肖像。

## 仍有边界

本批是已有剧情的场景化入口与信息组织，不等于完整角色演出。筑基主体已有玩家站立角色，同行支线已有全身人物；多数既有 NPC 仍为对话肖像，未补造行走帧、口型、全套动作、营救动画或全新地图碰撞。场景背景采用现有素材，局部器物热点还需逐地美术校准。PC 实际构图、鼠标/键盘和分辨率证据由主任务另记，不能用自动测试宣称沉浸感已完成。
