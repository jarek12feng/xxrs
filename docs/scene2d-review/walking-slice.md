# 开篇行走与现场人物实施

2026-11-03，本地实现。承接 scene-feedback-polish.md；不是全游戏行走或完整营救动画验收。

## 已接入

- 男性炼气主角使用 8 帧行走循环，左右转向、停下恢复站姿。点击地面行走，先点击地面取得焦点后可用 WASD / 方向键移动。选择人物/路标会走近；连续点击取消旧路径，略过走近或直接执行行动可立即结束移动，不强制等待。
- 持续按键改向保留步态，不逐次重播第0帧；窗口尺寸变化重建画面时保留归一化脚点。Escape 取消走动，略过走近返回地面焦点。
- 渡口、药庐、雾林、山祠有独立保守地面走廊和障碍。navigation.ts 使用纯 TS 可见图最短路，投影不可达目标至地面；不会朝上方山水、桌面和建筑直接直线滑行。入口进出保留方向：上山进入雾林/山祠从左侧，撤回药庐从右侧。
- 温蘅以透明全身素材站在药炉旁；现有陆迟在场。选中现场人物有轻微回应，不改关系或任务状态。
- 山祠成功救人后，在归路安全处显示药工，并有可查看的现场对象。未救人或保存失败不显示；已救人存档恢复直接显示，不重播成功。
- 保留原有三种准备、失败回撤、药圃两种取舍。没有新增世界时间、奖励、存档字段或动画结算。

## 素材

由内置 imagegen 生成，提示词和来源见 art/walking-prompts.md。最终接入 public/art/scene2d/hero-qi-walk-v2.png（1536×1024，4×2，每帧384×512）和 opening-people-v1.png（1254×1254，2帧，各627×1254）。首版步态有白雾，已弃用并存于 art/hero-qi-walk-v1-rejected.png；第二版通过深色场景实际观察确认白雾已去除。生成的 NPC 图实际尺寸不同于请求尺寸，加载以文件实测尺寸为准。

## 验证

- npm test -- --maxWorkers=4：106 文件、741 项通过；npm run build、git diff --check 通过，仍有既有包体提示。只读审查后修复持续按键重置步态、缩放丢失位置与 Escape 取消，再运行移动/寻路9项及构建通过。
- 纯寻路测试覆盖各场景可达、越界投影、障碍、无路、确定性；UI 测试证明点击地面/键盘不提交领域命令、不更改状态，锁定时拒绝移动，卸载释放渲染器。
- 1280×720 浏览器从公开命令药炉检查点实际操作：地面行走/改向 → 雾林出口 → 红绳 → 山祠 → 药草安抚营救 → 关闭药圃面板查看脱险药工。检查页不读写玩家存档，不等于本轮从新建角色完整通关。
- 截图 walking-pc.png 和 rescued-worker-pc.png 展示实机画面；静态截图本身不能证明动画流畅或路径全部无误。

## 后续边界

本批步态仅男性炼气主角；女性/其他境界保留原姿态兼容，未伪称拥有步态。人物仍为二维序列帧/静态 NPC；没有八方向步态或口型。后续已补男性炼气主角的取药、封装、稳阵及搀扶短姿态序列，范围和验证见 [动作序列记录](action-sequences.md)；仍不是高帧率完整动作动画。障碍为人工保守区域，不是全景逐像素碰撞，也没有开放背景上部全部地形。未完成 Windows、全分辨率和 Steam 发布验收。
