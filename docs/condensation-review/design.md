# 筑基大比奖励与结丹双路线

2026-11-02。用户在「评估筑基大比与金丹路线」确认完善并实施。本文覆盖此前金丹设计第 3 节“所有主药必须冒险取得”的限制；参赛与夺魁仍非强制。实施状态与验收须另记，不能以本设计作为已完成证据。

## 目标

让十年备战指向玩家自己的结丹准备。结丹需要关键主药，但可通过宗门内比或秘境取得。宗门玩家可转秘境，散修无需入宗，失败无需空等下一届。

完整循环：中期知道主药价值与两条来源 → 选择备战或探险投入 → 争得主药 → 继续完成筑基修行与本境考验 → 炼成凝丹丹药 → 准备灵地与可选护持 → 圆满叩关 → 用金丹能力完成首次远行。

## 奖励分档

| 首次成绩 | 固定奖励 | 用途 |
| --- | --- | --- |
| 一胜 | 灵石 24、护脉丹 1；保留现有一档普通补给 | 立即支持器物、功法与后期整备 |
| 两胜 | 结丹主药一份；保留第二档普通补给 | 替代首次秘境取主药，不替代筑基后期、圆满与归山成果 |
| 三胜 | 一次凝丹灵地使用或一次长老护持，择一；保留第三档普通补给 | 降低准备成本或提高本次把握，胜利有额外实用价值 |

- 主药随达到的新成绩固定授予，不与草药/回春散二选一，不存在选错补给漏领主药。
- 只按历史新成绩补差；同一命令、刷新、同成绩续届不重复发主药或培养。
- 一胜与零胜玩家可直接转秘境；两胜玩家无需夺魁。
- 旧存档不补造比赛结果、不追补旧奖励；未知存档保持拒绝覆盖保护。
- 已有灵地时不引导玩家选无用的灵地培养，仍可选一次护持。

## 秘境取药

秘境路线以实战和准备为核心，不能用交货代替。后期可开始争取主药；如果既有金丹切片安排圆满取药，必须在中期给出明确来源提示，具体开放节点在合并时统一。

初步落地方案是凝露药圃：备齐行装，选择合力分药或独行药床，再应对守药石偶。合力方是有自己结丹目标的修士，约好各取主药，额外药材归其所有；独行面对较强禁制，首通多得灵石与清心丹。都必得一份同用途主药，不决定金丹品质。既有潮潭/旧阵药圃若已实施，应复用其领域结构，避免为了本方案并存重复秘境模块；合力分药可作为路线取舍接入。

- 实际交锋使用当前主修、灵器、器纹、辅器与草药；赛前奖励能在这里发挥作用。
- 主动撤回不新增伤势，败退增加可恢复伤势；保留功法、成长和已知线索。
- 通关后明确获得主药，不用随机稀有掉落拖时长。
- 补取主药沿已知路线重试，不依赖拍卖随机目录；额外首通物资不重复发。
- 重试成本必须可预计且有恢复通路，比较药材、灵石、月份与有效选择，不以耗时惩罚未参赛者。

## 炼丹、灵地与叩关

主药来源只解决一项必要条件。正式突破还需筑基圆满 600、稳脉与贯流成果、长风归流、归山、凝丹丹药一枚、灵地与无伤状态。恋爱、结契、所有人物私事不成为额外前置。

自行炼丹用心得、草药和较少灵石；委托丹师以更多灵石替代技术与草药准备。两者成丹用途相同，不增加无保底炼丹失败。每次正式叩关消耗一枚成丹。

灵地允许租用或自行修复；宗门培养可替代一次付费，首次取得后可重复使用，不让突破失败导致重新买房。散修须有不入宗的可达来源。护持可选，明确增加多少把握和何时消耗；非冠军也可自行筹备相应功能。

突破前展示本次成功把握、耗时、年龄、余寿与失败代价。准备充分可达到确定成功；失败保留修为、功法、灵地与探索成果，只损失当次丹药、时间、护持及产生可恢复伤势。不可永久劣丹、封锁元婴或重置筑基主线。

金丹寿元基准总上限 500 年，年龄不清零，已有永久减寿保留。成功后立即进入一次需要金丹护体/神识的远行；原灵器仍可辅用，不能只更换境界文字。

## 状态与实现边界

- 大比拥有赛程、最佳成绩、已领奖档；结丹模块拥有主药库存、丹药、灵地、护持、叩关尝试与金丹后的首次远行。
- 通过结丹模块接口授予主药与培养，比赛不直接修改境界或跳过成长。
- UI 只发领域命令，成本与禁止原因由规则投影统一提供；战斗、探索、其他场景互斥，事件与寿尽优先结算。
- 新格式递增版本，更新校验、空白迁移与无法识别存档保护。奖励、关键素材与尝试次数之间应可校验，拒绝伪造来源及负资源。
- 不批量拓展金丹中后期、宗门间大比或元婴；现有获授权金丹首行若已在另一聊天实施，合并接入同一套，不保留两份竞争状态机。

## 验收

1. 三主修 × 宗门两胜 / 秘境两种取舍可达；记录真实公开命令下的月份、收支与操作数，不能用加资源的边界测试充当完整路线。
2. 两胜一负仍得主药，三胜选择不重复；输掉首场、弃权、缺席均可转秘境。
3. 失败后静养、补取、重炼、再次叩关能完成；未知档、损坏档、重复命令、存读档、事件与寿尽回归。
4. 提前获药不能跳过后期与圆满；散修、未恋爱者有完整路线。
5. 实际 UI 操作和窄屏检查；陌生玩家是否愿意备战、两路是否各有吸引力，仍需真人试玩。
6. 提交前完整测试、构建、差异检查。当前发生并行写入冲突，先确定单一实施负责方，再报告最终验收结果。
