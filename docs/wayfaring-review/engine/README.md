# 旅行引擎与剧情接入（2026-11-04）

## 接口与职责

`src/wayfaring/engine.ts` 是纯 TypeScript 模块，不读取 Vue、浏览器、随机数、领域存档，也不负责发奖。路线在配置阶段注册一次；剧情提供起点、终点与旅者投影即可获得行程：

```ts
const travel = createTravelEngine(placeIds, authoredLegs)
const quote = travel.plan({
  from: 'home', to: 'ferry',
  traveler: travelProfile(game),
  mode: 'auto', // 或 land / flight / sail
})
if (quote.ok) {
  // quote.plan: path / mode / distance / speed / movingMonths / fixedMonths / months
}
```

地点必须已注册、道路必须存在；不从地图像素猜距离，也不为任意两个地点制造通路。路线有方向、行路方式、最低境界，可表示单向航路。新增地区先注册地点与路线，再接剧情许可和抵达命令；同名渡口应使用不同ID或不同路线网络。

模块按精确耗时寻找可通行路线；同等耗时采用稳定排序。`auto`在具备的方式中选择最短整数月行程，再比较精确耗时。未知地点、无可用路线、没有相应移动能力均返回失败，不能变成免费抵达。已有内陆地图继续让玩家明确选陆路/御剑。

## 速度与装备扩展

`profile.ts`集中从游戏状态提取境界及移动能力。当前没有已定义的加速装备，因此效果列表为空，不能把武器攻击力或品质当作速度。

新增装备/功法效果时只需在该投影收集：

```ts
{ source: '某飞剑', mode: 'flight', flat: 1200 }
{ source: '御风效果', mode: 'flight', percent: 50 }
```

公式为`(基础速度 + 固定加速合计) × (1 + 百分比加速合计 / 100)`，三种方式分别计算。效果不授予移动资格；没有御剑能力的角色即使有飞行加速也不能飞。非有限值和计算后非正速度使该方式不可用。

每条路线明确采用距离计时或固定计时。距离段按有效速度算精确月数，固定段表示候潮、接驳、准备或已包含旅行的剧情行动。加速不缩短固定部分；全程最后向上取整为月，不逐段取整。零月近郊保留零月，不额外收费。

## 已接入

- **内陆六地**：原路径搜索由引擎替换。地图报价、快捷地点和实际出发调用同一规则投影；距离表与当前境界基础速度未改。
- **开场、青嶂、雾岭、炼气入境、凝丹/穿云壁、外海、诸宗会**：保留剧情命令到地点的适配器，原有路线、费用、准入条件传给统一引擎生成可播放行程。固定耗时仍取同一领域报价，不叠加距离月份。
- **内陆旅行、外海和诸宗会长途**：共用`advanceJourney`逐月推进循环，包含最后一月被事件打断后以零剩余时间续程的情况。剧情适配器只负责中断判断和最终抵达/奖励。
- **表现**：沿用RouteCanvas、PathTraveler和行走帧组件，地图动画不调用推进年月或发奖。长途确认出发后先保存，再播放。

现有不同章节仍各自保有剧情地点字段与抵达命令，没有本轮强行合并为全世界唯一角色坐标。自带准备/战斗的旧剧情命令仍负责其资源和事件结算；引擎不会用任意终点绕过这些条件。

## 存档

升级至v34。内陆出发保存完整行程快照（路线、方式、有效速度、精确移动时间、固定时间、总月数），续程读取快照与剩余月数。新装备、状态或境界变化不重算已出发的行程，下一次出发才重新报价。
