# 药乡入道与剧情入宗实施记录

2026-11-05。本地实现，未提交或发布。最新设计见 [入道与宗籍](../initiation-design.md)。

## 已接入

- 开场在实际场景中交代药乡、药运、老药师调息、温蘅引荐、主动辞别与求道心意；先卸药、试息，再进入药篓营救。
- 新角色灵石为0，没有储物袋与正式功法；公共命令在取得入道行装前拒绝提前劳作赚灵石、学习、购买或修炼等绕过。营救谢礼暂存，回药坪后结清。
- 药坪求学、可失败重试的护路绳阵、亲历引荐、门规和正式拜师。散修可立约取得基础抄本与行装，后来仍可求入。两路不重复发钱、背包或功法选学资格。
- 只有正式弟子有宗门面板和入口；储物袋、功法与洞府按入道行装持有开放。新档不再显示开场自带装备的假象。
- 独立 `src/initiation/` 保存规则与组件，命令执行重查资格和库存；UI不改领域状态。版本43新增入道持久状态，v42及更旧档保留既有资源／宗籍，不补剧情和奖励；未知版本继续拒绝覆盖。
- 两张场景背景由独立聊天实际生成，主任务检查后接入 `public/art/initiation/`。原图1672×941，交付1920×1080 WebP，为放大导出；[原图、提示词与美术QA](../art-candidates/initiation-20261105/README.md)保留。

## 回归组织

改变初始身份会使旧测试把“已有修士”的操作错误地施加在未入道少年上。相关既有规则／UI单元用例改为显式 `tools/cultivator-fixture.ts`：旧式12灵石、已持旧行装，不伪称正常新档。真正新档入口仍是 `core.createGame` 的0灵石；`tests/initiation.test.ts`、`tests/initiation-ui.test.ts`覆盖新档、实际初习、试阵失败恢复、两种获得渠道、拜师门槛、延迟回宗、幂等与迁移。全程命令策略与检查点通过 `seekerStep` 执行实际新剧情获得行装，不使用这个隔离夹具。

## 验证

- `npm test -- --maxWorkers=2`：186个文件、1295项测试通过。限定工作进程避免大型路线矩阵争用CPU；包含当前并行修改的测试，不代表全部变动均由本任务制作。
- `npm run build`：类型检查和生产构建通过；仍有既有大分包提醒。`git diff --check`通过。
- 生产预览正常新档，无状态注入：卸药→稳息→求道心意→漂回药篓→药庐文火备药→循红绳→救出药工→带回成株→药坪求学→拉紧双绳失败→辨受力重试→亲历评议→门规→拜入丹堂→刷新继续→选学长春诀→查看储物袋。核实拜师前无宗门/行装入口，拜师后入口出现、24灵石和4灵草入袋，刷新后宗籍保持。
- 实际浏览器视口319×669；修复窄窗口现场高度收缩后，正常点选木匣与功法通过。拜师按钮曾受布局影响，使用键盘Enter完成；不据此宣称桌面鼠标完整验收。截图是实际JPEG，未冒称1280×720。
- 散修立约与后续入宗的奖励幂等性由规则和App组件测试验证，本次未另建正常新档完整点完散修分支。

## 边界

本轮开篇未新增正式退宗系统、凡俗货币经济或全世界NPC模拟；行装仅负责入道授予，容器后续成长沿用对应模块。药坪试阵是可选择、会反馈失败原因的局部交互，没有完整逐帧拉绳动画。未验收全分支连续至元婴、Windows/Steam、陌生玩家60–90分钟体验。
