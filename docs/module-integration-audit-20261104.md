## 核实后保留

- `legacy-v1/v2/v4`、旧道路/冒险校验器仍由迁移入口调用。它们记录旧数据结构，不是当前规则的第二份实现，不能直接删除。
- 筑基 `advancePlot` 的 `travel` 分支由旅行引擎在真正抵达后调用，负责首次到渡等剧情事实。审查初期误判为无调用并删除，类型检查与章节回归发现依赖后已恢复；最终此分支无改动。
- `world`、章节状态与目录的部分转导出仍有消费者。纯转导出并不重复业务计算；本轮不机械替换所有公共路径。
- `chapter` / `world` 的月循环包含活动收益、故事时钟、闭关中断和生命周期处理；不等同于单纯等待工期。旅行引擎还维护剩余路程，不能直接替换成一次性的时间推进。
- 战斗、装备已通过公共入口接入；存档中的章节战斗字段、章节准入、奖励和去向仍归章节管理。
- 社交、炼气/筑基剧情、拍卖等仍有直接资源奖惩；这不代表所有收支已统一。若继续迁移，应按具体命令同时处理报价、失败返回和奖励事实，不能把每行 `+=` 机械替换为忽略错误的结算调用。
- 剧情交互协议目前主要覆盖凝丹、外海和诸宗会。早期章节选项仍有独立结构，需要按完整交互流程逐章推进，不能把本次清理称为全剧情协议统一。

## 继续优化与设计同步（2026-11-04）

### 新完成的接入

| 流程 | 改动 | 失败与恢复 |
| --- | --- | --- |
| 拍卖丹药、器物取得 | 丹药成交费用与库存增量统一结算；检查装备/赠书操作结果 | 库存满时拒绝出价，不推进拍次、不改变价格、不付款；可放弃或离场，腾出容量后重试 |
| 炼气人物交付与普通委托 | `personQuote`、`qiQuote` 提供成本及奖励；交付成功后才消耗战利品和记录完成 | 蟒蜕换药的两类奖励一起到账，任一溢出则都不发；不吞战利品或委托资格 |
| 炼气三路整备、入境、炼化与战间通行 | `preparationQuote` 与统一资源接口处理灵草、灵石、护脉丹、贡献 | 失败不推进准备事实；战间扣料失败不新增伤势或开始下一场 |
| 筑基成长与回访 | `growthQuote` 同时给出成本、奖励；执行检查返回值 | 榜单补给和回访失败不记已领/已回访；不发生部分扣费或部分发奖 |
| 照玄分宝与寄药 | 补偿、补给、止争材料复用统一结算 | 报酬收不下时保留原分取现场/收信资格 |
| 任用差事 | 草药成本、灵石和贡献报酬一起校验，成功才记亲历 | 满余额拒绝时不耗月份、不扣草药；正常时沿用首次/熟路差事数额 |
| 交互协议 | 显式 `settlement.cost/reward`，覆盖旧平铺费用推断；炼气人物与照玄选项接入 | 不再将报酬的正数灵石当作费用；命令重验当前状态，投影资源表不写回原报价 |
| 未使用声明 | 清理测试与工具残留；启用 `noUnusedLocals`、`noUnusedParameters` | 正式类型检查和构建持续拦截新残留，覆盖上一轮严格检查未通过的状态 |

本轮统一资源接口支持既有 `journey.contribution`，没有新建积分、奖励账本、存档字段或迁移版本。正常价格、奖励、时间、随机顺序和剧情立场均保持；新增拒绝发生在容量不足等原先可能生成非法状态的路径。
