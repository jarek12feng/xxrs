# v0.12.0 · 归途上的药篓

## 体验目标与范围

围绕前 30 分钟的首段体验打磨“调查—修行方法实践—营救—取舍—人物回应—继续求道”的路径。30 分钟是设计观察窗口，不是强制计时，也尚未通过陌生玩家计时验证。没有增加挂机等待或用重复事务补时长。

修仙是主线：炼气修士学习灵药、分流或护体以穿越旧阵；雾岭灵流需要筑基之身承受，成长服务于追查失踪修士。爱情、探险、悬疑从修行、机缘和道途产生，不新增现代恋爱支线或独立侦探系统。本版文字原创，借鉴类型叙事结构，不移植具体小说人物或桥段。

## 一篓灵药，两种后果

所有成功营救方法均可选择；不会因为选剑道就强制取药，也不会把取药救人写成恶行。幼株不动、药工均安全回家。

- **留下成株（return）**：不额外发灵草；守祠妖修教护根手法。第二卷回访药工会提及留种与山下仍需补药的代价。第三卷旧药圃可独行、无医道心得、无灵草完成 attune，保留其他已有解法。
- **带回成株（takeHerbs）**：温蘅先用于渡口伤者，再给玩家灵草 4；可以炼丹或交付山口伤药。药圃这一季空置，药工约定来年补种，没有护根解法。
- 两者均沿用原有灵石 12 与对应方法成长奖励。选择先通过命令原子结算并保存，再更新画面、人物回应和音效。保存失败原状态保留。

## 音频

src/audio.ts 在表现层以 Web Audio 合成风雨底噪与轻音阶提示，无下载、外链、第三方素材或游戏 RNG 访问。四种场景氛围以滤波变化区分，目前不包含完整背景配乐或人物配音。

首次默认静音，开启后存于独立 localStorage 偏好；下一次启动仍需用户交互激活音频。环境声与行动音效可分别调到 0。切后台暂停，返回后按启用状态恢复；卸载页面关闭 AudioContext。浏览器不支持时显示提示，不阻塞游玩或存档。自动修行不连续播放音效；所有剧情信息均有文字，不依赖声音完成任务。

## 本地配乐试听（不进入发行包）

用 `npm run dev:music` 启动，入口为 `http://127.0.0.1:5191/`，沿用该地址的原有存档。点右上角“开启声音”，在“系统菜单 → 显示与声音”调整独立的剧情配乐音量（默认 45%）。普通 `npm run dev`、`npm run build` 和 Windows 打包均不启用这些曲目。

首次准备素材（macOS 自带 afconvert；Python 3 标准库）：

```sh
python3 tools/prepare-local-music.py /Users/admin/Documents/xxrs/music.zip
npm run dev:music
```

处理后的五首 WAV 仅放在被 Git 忽略的 `.local-music/`，不放入 `public/`。Vite 中间件仅在开发服务且 mode 为 local-music 时提供固定白名单路径。客户端播放器仅在此模式动态导入，生产构建移除；Electron 发行文件白名单仅包含 dist、desktop 与 package.json。原压缩包及处理后的录音均不提交。

| 曲目 | 接入场景 |
| --- | --- |
| 新桃旧符 | 山居、药庐、坊市、救人归家 |
| 悬疑1 | 雨夜渡口、雾林、废驿、迟到的信、重访旧祠 |
| 少年游 | 山口行营、灯下分路、旧药圃同行 |
| 破阵乐 | 首次山祠救人、青嶂关、雾海回声阵 |
| 御剑江湖 | 过关后的云外长路与云栈旅亭 |

处理策略：去掉原曲头 2 秒、尾 4 秒，首尾 2 秒线性交叠形成循环。RMS 目标为 -23 dBFS，峰值上限 -3 dBFS；两首动态较大的曲目优先保证峰值，因此平均电平约 -23.7/-23.8 dBFS。此为信号电平平衡，并非 LUFS 响度母带或人工听审，实际听感由试玩反馈继续校准。分析数据保存在 `.local-music/analysis.json`。

播放器在新曲可播放后才淡出旧曲，约 2 秒完成主要过渡；同一场景更新不重播。事件对话、情缘对话、人物档案和人物行动回执出现时，配乐平滑降为当前音量的 30%，关闭后恢复。切后台暂停并保留位置，回前台淡入续播；关闭声音立即停止。加载失败显示提示，不阻塞游戏与保存。音频偏好独立存于 localStorage，不改领域状态或存档格式。

新增播放器测试覆盖手势解锁、循环标记、淡入/切曲、对话压低与恢复、后台暂停、迟到的播放回调、加载失败和场景映射。实机试听仍需确认旋律循环点是否自然、短曲长期循环是否疲劳，以及阅读时音量是否合适。
