# v0.13.0 青嶂关：护送与旧阵

## 试玩入口与边界

完成营救和坊市补图后，在青嶂关或山口行营接取“护送与旧阵”。本版先验证一个完整循环，未铺开所有地图关卡。新委托为自愿接取，旧流程仍可继续；接取后必须完成三关，才能实施三条归路或走旧路过关。已经通过山口的旧档不倒退、不补发奖励，下世可体验。

山道护送（战斗）→ 古阵寻踪（神识/心得，或灵草）→ 守阵交锋（需筑基）→ 护身诀与山口解法 → 原有雾海后续。剧情加入药队名单、失踪亲人的药签与被改造的守阵傀儡，不改变原有成年感情线。

## 经济与难度

日常继续按月份消耗寿元，沿用灵石、灵草、伤势，不增加现实时间体力。新关每次开战或处理阵眼耗一月，分别扣灵石 2/2/4。主动撤退不新增伤势但不退成本，战败伤势 +1；受伤 3 层起必须先恢复。已过小关保留，恢复气势发生在重新付费出战时。每关首次奖励灵石 4/6/12、灵草 2，不可刷奖。阵眼的草药方案另耗灵草 4。

月推进复用 chapter 的死亡和约期钩子，新 travelMonth 不发劳作或功法收入。碰到人生事件时先暂停，不扣挑战补给、不创建战斗；该月已经消耗。死亡先于奖励。

气势 = max(16, 36 + 根基 - 伤势×5)。基础伤害 = 5 + floor((神识 + 心得×2 + 剑意 + 根基)/4) + 装备灵剑每阶 2。护身诀减伤 2，灵瓶每阶减伤 1。正确应对伤害 +6；敌人基础攻击在正确应对时 -5，错误时 +3，再扣护体，至少 1。击倒敌人后不再承受反击，最多 12 合。无额外随机掷骰，刷新不会重置回合或补给。小关直接教应对，大关只描述蓄力和破绽。

最低准备建议为筑基、根基 6、神识 6、心得 2，非保证胜利的硬门槛。不同路线继续通过原有功法/灵器/修行强化；原有三种山口解法各自条件仍保留。

## 代码与存档

- src/expedition/content.ts：关卡、敌人提示与剧情配置。
- src/expedition/rules.ts：纯 TypeScript 规则、能力投影、命令条件、奖励、校验。
- src/expedition/ExpeditionPanel.vue：选择与提示；通过 Intent 发命令。
- src/expedition/BattleStage.vue：轻量 SVG/CSS 人物出招、格挡、辨影、受击与胜负演出；尊重减少动态效果。
- world.ts：命令分发、共享时钟接线与存档迁移；RoadPanel 只接入组件，App 不新增关卡规则。

状态版本升至 12。v11 迁移添加空的 expedition，不改既有资源、随机种子、剧情或归路；首次保存保留 original-v11。更早存档沿既有迁移链升级，未来版本和损坏状态拒绝覆盖。战斗中拒绝其他领域命令，撤退后恢复正常修行；轮回清空本世关卡。

## 验证与局限

254 项测试（28 个文件）通过；npm run build（含 vue-tsc）和 git diff --check 通过。这次桌面烟测的 write/read/corrupt/recovered 四阶段均通过、进程正常退出。此前观察到的 macOS Electron 原生退出崩溃本轮未复现，不把本轮通过当作已经修复原生问题。

60 组公开命令模拟：两条道途 × 三种资质 × 十种种子，各运行两遍得到一致汇总。基础准备与正确应对均完成三关，关卡部分总计三个月、净灵石 +14、零新增伤势。另覆盖连续错误应对失败、养伤重试、撤退、两种阵眼方案、后续医道归路、资源不足、事件/死亡优先、重复命令、重复奖励、轮回清理、旧档备份、战斗中途 IndexedDB 读回。模拟入口 tools/expedition-simulation.ts，可用 esbuild 打包后传 --run 查看结果。

浏览器在仅内存的独立验收页验证了实际出战、守势/反击/凝神回合与小关奖励、其他行动锁定。验收页已清理，未操作用户存档。演出是第一版分层 SVG 动作，不是成品角色帧动画；实际首次 30 分钟的节奏、不同玩家策略的难度和长期资源平衡仍需真实试玩，本轮没有宣称完成长期平衡或 Steam 发布。

## 本轮试玩打磨：引导与交锋可读性

营救回访后优先引导坊市补图和炼气期护送，不再先要求长期修行。两处小关完成后才提示为守阵交锋修炼、筑基；回访完成后的引导按钮会真正前往坊市，不会再次派发已经完成的 thanks。委托中按当前伤势、补给和阵眼条件提供一月静养、劳作、研读、凝神按钮，均发原有命令，不直接修改状态。准备建议由独立 presentation.ts 投影。

战斗区将复杂公式收起，显示双方可读气势条与当前数值。劫药客使用蒙面持刀造型，蚀阵傀儡使用石甲和阵核造型；新增蓄力、幻影和阵核暴露提示，保留减少动态效果选项。sound-cues.ts 独立管理攻击、格挡、辨影、受击和胜利的合成音色；action-sound.ts 从成功保存后的状态选择声音，复用原有静音、后台暂停、音量与销毁控制。

没有更改伤害公式、奖励、资源成本或存档结构（仍为 v12）。新增从公开命令开始、未经筑基准备的首关测试，覆盖两道途三资质：正确应对可在炼气期通过。包括原有 60 组完整路线回归，共 260 项测试、29 文件通过；构建（含类型检查）与 diff 检查通过。浏览器隔离页验证了守阵辨影、格挡后的真实气势条与动作，未操作用户存档；临时验收文件已移除。没有把自动化路径验证称为完整 30 分钟真人试玩，也未据此宣称长期数值平衡完成。

## 功法打法与名单回收

主修功法现在改变青嶂关交锋结算，效果来自实际装配而非角色道途标签：

- 听松剑经：反击伤害 +8；未击倒敌人时本回合承伤 +2，允许冒险抢攻。
- 长春诀：有灵草时守势伤害 −2。先结算受击，存活后消耗灵草 1 恢复最多 7 气势，不能超过入战上限。无草使用普通守势；致命伤不救回，击倒敌人的回合不耗草。
- 归元息：辨影伤害 +2、承伤 −2；对守阵傀儡改为伤害 +7。效果与正确应对叠加，其他动作不获得加成。

资源、气势和敌方状态全部由纯 combat.ts 计算、rules.ts 命令落地。功法说明和战斗按钮提示同步展示特性、代价。战斗中依然禁止换功法，回合上限依旧 12，不增加额外随机数或存档字段。现有 v12 包括未结束交锋可继续读取，后续出招按本次功法规则结算。

新增独立 resolution.ts 与 ExpeditionResolution.vue，在守阵完成及旅亭结语中展示：转运册记载被扣作阵引的药工，抢药箱是为了销证，守阵傀儡是被人为改造。郁青依据营救时护根/带药/旧档记录和三种归路表达不同回应。它们只读已有选择，不伪造新选择、不增加好感、不重复发奖。已完成旧档可回看新增结语。

雾海接信、废驿解阵、归来分享通过既有命令回收线索：交接簿核实姐姐是随队救治者，不是押送者。只走药圃而未调查废驿的玩家，分享时明确保留未查实的部分，不提前获得姐姐身份的结论。

验证：268 项测试、30 文件通过；构建（含类型检查）与 git diff --check 通过。新增三功法 × 两道途 × 三资质 × 十种子，共 180 组公开命令路线，每组运行两次状态完全一致；采用对应提示的正确应对时全部可过关且资源非负。另覆盖抢攻代价、耗草与气势上限、致命伤、终结攻击不耗草、幂等命令、中途存档、功法切换锁、各选择的结语及实际雾海接信/解阵命令。该验证证明路线可行与边界正确，不代表所有自由策略已达到最终平衡。
