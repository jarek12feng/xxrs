# 二维开场首批实施与验证

后续整合：见 [已有剧情场景化整合记录](scene2d-review/all-story-rollout.md)，以下保留首批实施证据。

2026-11-03。统一规则见 [二维场景与修行时间统一约束](scene-and-time-contract.md)。本批为本地实现，不代表全游戏二维化或 Steam 发布完成。

## 已实现

- TypeScript + Phaser 3.90 场景渲染按需加载；开场渡口、药庐、雾林、山祠四处场景接入。营救后的药圃取舍仍在山祠现场，不切到不相关的露台背景。
- 可发现的对象标记：药篓、陆迟、药炉、铜铃、两条林路、阵门、药圃和出口。选中对象让角色短距离移位，并展示该对象对应的观察与合法操作。鼠标/触摸/原生按钮键盘入口共用。
- 救人成功后从持久化状态显示阵光平息与已稳住的门；开场不再用全屏成功对话框遮住现场。准备充分不等于救人成功，两种状态分开。
- 长背景与可选见闻折叠；开场不叠加重复行旅目标；领取功法时保留既有药圃后果，避免收起指引后丢失选择回应。
- 首册功法提供“学会并主修”，一次命令完成领取与装配。已有主修时明示替换，已学功法保留。底层 learning 命令新增可选 equip 参数，默认仍维持原来仅领取行为，不新增存档字段。
- 功法页按已装配、已拥有、未学会排序。领取后可在药庐外试招，调用真实战斗公式对比未装主修/当前主修；练习无奖励，不耗灵草、不留伤势、不推进时间。

## 模块和状态边界

- `src/scene2d/opening.ts`：纯只读投影，把既有合法 adventureOptions 关联到对象。无新增奖励、门槛、月份或随机。
- `src/scene2d/renderer.ts`：只接收场景配置，不能取得 State 或 dispatch；负责图片、角色移位、阵光与短淡入，隐藏页面休眠，卸载销毁引擎和监听器。
- `src/scene2d/OpeningScene.vue`：对象选择是临时 UI 状态；实际行动仍经 App 的 dispatch → 保存成功 → 更新状态。保存失败保持原场景与操作。
- `src/scene2d/FirstPractice.vue`：可选只读演示，不作为任务资格或存档进度。
- AdventurePanel 成为组合入口，未把引擎代码加入 core.ts。App 仅进行组件组合、开场回执与指引显示协调。

本批不改变旅行和闭关数值。开场原有三条准备路线、失败恢复、快捷假路与两种药圃结果保留。分境界计时、远行与约定规则已统一成文，尚未按新文档逐个审计所有旧日程实现。

## 验证

- 全量 `npm test -- --maxWorkers=4`：96 文件、698 项通过；初次默认并发下一个已有重平衡测试超时，限制工作线程后完整通过，未修改该测试断言/超时。
- 新增三路线对象动作覆盖、只读投影不变更状态、固定种子/时间与存档往返、失败回撤、成功后现场变化、领取即装配的幂等与死亡冻结。
- UI 测试保留真实命令与保存边界：保存不提交时门不变、忙碌禁操作、持久化后显示药圃取舍、卸载释放渲染器；原界面测试更新为“先点对象再行动”，继续检查保存失败、音频和奖励。
- 浏览器独立来源 5293：新建角色 → 调查药篓 → 配药 → 红绳路线 → 山祠营救 → 带回成株 → 听松剑经自动主修 → 反击试招。实际试招显示伤敌 6→14、承伤 15→17，与剑经规则一致；全部仍为第 0 月。营救存档重新载入保持阵门已稳和药圃选择待决。
- 浏览器本次读取错误日志为空；检查窄屏（约 319px 宽）对象标记、操作与试招。截图：[山祠](scene2d-review/shrine-narrow.png)、[试招](scene2d-review/first-practice-narrow.png)。这是开发检查，不是移动真机或陌生玩家证据。
- 生产构建与 `git diff --check` 通过。Phaser 动态块约 1.21 MB（gzip 331 KB），与主包分开；构建仍有大块体积警告，不把引入引擎称为性能优化。

## 素材

新无人渡口图：`public/art/scene2d/ferry.png`，2026-11-03 通过 imagegen 生成。提示要求：中国修真山中雨夜渡口，侧上方固定机位，左侧渡船与药篓、右侧上山石阶，前景连续可落脚地面，青灰山水和暖灯，无人物、UI、文字、现代或西式物件。原生成图保留在本机生成目录；工程内含发行引用副本。

其余药庐、雾林、山祠背景及主角、陆迟、灵草图复用现有资源。NPC 不用其他怪物冒充。当前主角以已有姿态图移位，尚非完整多方向逐帧行走动画。

## 未完成与下一步

- 本批是固定视角对象交互切片，不是可自由行走、带碰撞/寻路的俯视角 RPG。对象位移不计时间，也不作为领域资格。
- 尚未给温蘅、守祠妖修和药工制作新的场景动作组；当前相关动作仍由现场说明与阵光变化表达。不能声称救人已有完整角色动画。
- 青嶂、筑基、金丹仍沿用现有表现；战斗策略深化、法宝主动场景用途、后续选择的长期差异未在本批实现。
- 未进行 Windows 实机、Steam 构建上传、手柄验收、完整桌面分辨率矩阵、陌生玩家或 60–90 分钟自然首玩。须先让用户评价本切片，再决定下一批场景推广范围。

## 2026-11-03 第二轮：全视野场景布局

用户再次明确要在修真世界中交流、行动，第一轮图片卡片加折叠长文未达到预期。本轮撤去开场文章式容器，渡口、药庐、雾林、山祠改为视口背景与现场对象入口。标题/短目标在边缘；选中对象才出现底部操作层，长见闻和行动经过按需展开。隐藏开场重复导航和目标卡，随身功能保留；其他区域尚未迁移。底层月份、奖励、成功条件及存档格式未在本轮改变。

渲染器按容器尺寸生成画布，背景等比覆盖、人物保持比例；窗口变化重建表现，卸载时清理监听和定时器。界面展开状态不进入存档。调查药篓后眼前目标更新为上山，避免仍提示重复调查。

验证：
- 桌面浏览器 1280×720，新角色进入渡口、选择药篓、调查、选中石阶、进入药庐、选择药炉，已实际操作；年月保持 0。截图：[渡口常态](scene2d-review/ferry-immersive-desktop.png)、[药庐交互](scene2d-review/apothecary-immersive-desktop.png)。
- 用临时同源 iframe 创建 390×640 CSS 视口，读取同一测试角色并选择药炉，确认操作、关闭按钮和底部功能可见；[窄视口截图](scene2d-review/apothecary-immersive-390.png)右侧黑色为空白外层页面。不是移动真机验证，临时检查页已移除。
- UI 回归增加见闻默认隐藏、展开和收起、结果经过折叠展开、收起对象操作；继续检查保存失败不提前变更现场、锁定操作、后果展示和销毁引擎。
- 全量 96 文件 / 698 测试通过，生产构建和 diff 空白检查通过。构建仍有 Phaser 大块警告。

未达目标的部分：现有药庐背景的透视/落脚面与叠加角色尚不协调，人物没有完整行走、交谈和操作动作；缺少温蘅、被困药工等现场角色以及配药/营救过程。此次只完成场景界面基础，不能据此宣称世界沉浸感已经验收。后续按统一约束第 8 节逐场景补齐人物、行动与结果，不继续以增加背景数量代替体验。

## 2026-11-03 第三轮：PC 场景交互重构

本轮由主任务实施场景 UI 与集成，两个子任务分别实现只读投影、渲染器，第三个子任务只读审查。未创建用户侧独立任务，也未提交或推送。

- 接入专门为角色活动留出连续地面的药庐背景，修正旧图中站在前景药桌上的构图问题；素材、最终提示词与生成来源见 [药庐素材记录](scene2d-review/apothecary-floor-v1.md)。
- 现场入口区分交谈、器物与道路；温蘅与陆迟使用已有肖像，交谈内容改为既定剧情中的简短现场回应。按钮显示短动作，准备/冒进方法、未准备挑战和药圃不可逆后果仍直接可见。完整 action/label 保留，领域逻辑不变。
- 操作保存后在交谈层即时显示真实结果首句，完整经过可展开。保存失败不改变场景，不展示准备或营救成功。
- 渲染层加入接地阴影、纵深缩放/排序、朝向与距离相关短位移；渡口轻雨、雾林薄雾使用确定性表现时间。已保存准备/营救状态首次变化播放已有护身姿态；读档、重复同步不重播。减少动态模式不播放环境、位移动画和姿态过场，后台及卸载清理保留。
- PC 场景使用统一 16:9 画布，窗口其他比例留边，保持背景、角色和热点的相对构图；不再让宽高比变化单独裁切背景。窄屏仍为次级适配。
- 修复 Esc 优先级：全局模态先关闭，回到现场后再按 Esc 关闭交谈并归还焦点，不误开系统菜单。营救仍在山祠时不再显示虚假“抵达归途”，现场名改为山祠药圃。

### 本轮验证

- 全量测试 98 文件、705 项通过；生产构建与 `git diff --check` 通过。Phaser 大块警告仍存在。
- 实际 UI 操作：从此前新建测试角色的药庐进度继续，配药→准备→入林→循红绳→阵门营救→药圃后果展示；保持第 0 月。重载后仍为山祠药圃，阵门已稳。
- PC 使用 1920×1080 CSS 同源 iframe 进行布局和鼠标/键盘检查，缩放至 1280×720 预览截图；这是实际浏览器布局检查，不是 1080p Windows 显示器/缩放验收。[药庐](scene2d-review/apothecary-pc-refactor.png)、[山祠](scene2d-review/shrine-pc-refactor.png)。临时检查页已移除。
- 实际验证“药圃操作→打开储物袋→Esc 关闭背包→Esc 收起现场操作并聚焦药圃”，不再误开菜单。自动回归覆盖保存失败、三条准备路线、错误准备与回撤、同场营救不弹到达通知。

### 仍未完成

没有完整多方向行走帧、寻路/碰撞或自由移动；已有护身姿态与短位移不等于完整行走。温蘅现场全身角色、药炉具体操作动画、守祠者和被救药工的完整营救演出尚缺。后续区域、功法领取与练习页仍有旧布局。2560×1440、Windows 系统缩放、全屏切换、手柄及 Steam Deck 尚未实测；本轮不宣称整体重构完成或 Steam 可发行。
