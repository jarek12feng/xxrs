## 目标

玩家闭关、旅行和历练时，世界与旧人仍有消息。消息来源（道友、道侣、执事、拍卖行、驿使、看客）与用途（八卦、近况、机缘、通知、邀约、求助、回音）分离。不是每封信都产生任务；信件不能替代准备、真实旅行与现场挑战。

本轮先以已实现事实生成消息，不引入全体 NPC 人生模拟。恋爱与结契不构成收取普通道友消息的门槛，不自动提升关系或给奖励。读信、确认消息、答应邀约彼此独立。

## 送达、阅读、关注与响应

- 新角色为空信册。公共命令成功后，在最终私有状态上调用 `deliverMessages`；不会从 Vue 渲染、计时器或现实时间推进。
- 打开面板时可以通过 `collect` 命令收取当前仍适用消息。旧档迁移不立即伪造历史信件，之后收信日期记为实际收取的当前游戏月。
- 普通消息在批量动作结束后收取，不逐月补发几百封已经过期的拍卖通知。当前近况可能附带旧笺，沿用原剧情文本；未逐阶段收到的消息不伪造当年的收信日期。
- 用稳定 ID 去重；同一拍卖以会场+会次去重，同一人物以原近况阶段去重。重复点击与读档不重复发信、确认或奖励。
- 正文、来源、标题、收信日期是持久快照；过期、已赴约、已完成等为只读现况投影，不改写旧信。
- 点击展开后经命令标记已读，保存成功后 UI 更新；读信本身不接任务。未读用“未读”徽标与亮边，已读用“已读”徽标，不能只靠颜色。全部/未读/已读快捷筛选；分类和关注筛选另保留。主界面传讯入口显示未读数。
- “记下此事”只用于关注筛选，不代表接受、自动代拍、自动赴会或自动停关。首批没有通用约定日历；会期停关与闭关预估继续由已有领域处理。
- 战斗、探索险阵、旅行途中、待处理事件、行功和寿终期间禁止新增传讯操作。旧信册不是跳过现场互斥的通路。

## 模块接口与所有权

新增 `src/correspondence/`，纯 TypeScript 规则不依赖 Vue、DOM、存储或系统时钟。

- `state.ts`：`Correspondence` / `Letter`、`freshCorrespondence`、`validCorrespondence`；7 类信息，3 类可信程度；信册上限 2048，保留所有旧信、不自动清理；UI 每页12件事。该上限是防畸形档边界，未来扩展长寿境界或大量动态消息前需重审容量与归档策略。
- `sources.ts`：`messageSources(State): MessageDraft[]`，只读源适配器。不推进人物成长，不授予地图知识，不消费随机种子，不调用命令。
- `rules.ts`：`deliverMessages`（仅可修改命令的私有草稿）、`correspondenceQuote`（公共条件）、`runCorrespondence`（阅读/关注/回应/核验）、`messageStatus`（旧信对应事件的当前状况）。
- `CorrespondencePanel.vue`：列表、阅读、筛选、响应按钮与分页，只发 `Intent`；地图/人物/榜单导航只打开现有页面，不修改角色位置。
- `world.ts`：仅组合状态、分发、结算后送达、保存校验与迁移；`normalize` 保留同一人生的信册，新人生为空。
- `App.vue`：随身功能入口、未读计数、面板组合与导航。传讯不另弹通用行动回执，结果留在信侧；失败原因接入 `action-diagnostics.ts`。

照玄约定仍归 `secret-pact`，人物确认仍归 `golden-story`，拍卖会期仍归 `auction`。新增消息不应复制一套拍卖、人物或剧情状态。

## 存档 v47

在 v46 后新增 `correspondence: { letters: [] }`。只在迁移最终边界补空域，不重复升级拍卖，不补历史来信、经历、约定或奖励。旧版本依次沿原链迁移；v46 先按 v46 校验，当前损坏档与未知未来版本拒绝覆盖。保存沿既有 save.ts 备份逻辑，v46 首次保存可保留 original-v46。

校验覆盖数组容量、唯一 ID、消息类型、文本长度、来源、阅读/关注布尔值、响应值、合法目的地与日期。不用“已读”推导接受，不用“已送达”推导人物已确认突破。

## 后续接手顺序

1. 给已有旧友补少量有具体后续的回信，仍由人物领域执行结果。
2. 已完成基础事件往来归并；下一步再增加可核实传言的来源链，不把消息分组当作传闻求证玩法。
3. 接入独立约定日历：用户选择是否停关、准备期和真实路程、迟到/婉拒/完成的回音。先定义统一 timeline 契约，不从消息模块逐月模拟。
4. 在有实际玩法之后添加法宝出世、遗迹显现、他人榜单与筑基/元婴消息；未实现内容只能作为明确远方见闻，不提供假入口。
5. 场景内驿使、洞府留讯台与收信演出可复用统一信册；首批入口在随身功能，没有新造所有地点收信动画。

每个新增来源须注明事实归属、发现/信路条件、稳定 ID、信息可信度、是否可行动、处理失效的规则。可行动消息必须有现成命令或完整的新玩法；不能仅添加一段催玩家办事的文案。

## 主动联络首批（2026-11-05）

已接入苏婉宁（男性角色、已经相识且留下联络）与叶照（已经收到照玄邀约）。`personal.ts` 提供联系人、寄信条件、发件快照与到期回执，公共命令新增 `write {recipient, topic}`；主题为报平安、问近况、邀约、暂缓相约。

- 发件为已读 Letter，`personal:<recipient>:<topic>:<chapter>`；回执为 `answer:` 同后缀，独立未读。复用现行 Letter 格式，不增加存档版本；JSON 读档保留候信状态。
- 普通回执至少一游戏月后由正常命令末尾的 `deliverMessages` 送达；打开面板不会推进时间，现实离线不会催生回信。同一联系人有未回信时不能连续寄件，同一剧情阶段同主题只发一次，不加好感、奖励或随机数。
- 邀约/暂缓直接复用原有规则：苏婉宁复用金丹 `reunion invite`，叶照复用 `pact promise/decline`。这些动作当下就登记原有约定，后续送达的是书面回执；不是远程赴约，不跳旅行或现场条件。已有苏婉宁约定不可被“暂缓”取消。
- 回音只使用可靠状态。无可靠当前联系时返回驿使“未能确认本人收信”，不能推断死亡、自动核验凝丹或补发经历；叶照已进入探府后不杜撰其远方近况。
- `history.ts` 是独立只读接口；只有已送达且署名苏婉宁的报平安回音，才在真实古渡见面时追加一句承接。没有回执或只有驿使回执不触发。
- `PersonalContacts.vue` 只发命令；`view.ts` 将发件与回音按联系人归组。原有邀约事件组保留。

边界：这不是自由聊天或完整 NPC 通信模拟。尚未接入主动分享具体所在地、更多联系人、人物特有长期问答、运输距离差异、完整道侣专属往来；普通近况回信不替代可靠剧情信件。继续扩写应沿本接口增加有证据的内容，不把未实现支线编成当前事实。

## 世界事实与消息闭环（2026-11-05）

新增 `world-events/knownWorldFacts` 只读事实接口；传讯 `events.ts` 负责书信表述。首批三种事实为拍卖实际成交、外海遗迹阶段、筑基榜已结算首胜。世界演化与传播如何继续分离见 [世界演化设计](world-evolution-design.md)，当前没有实现通用模拟引擎。

拍卖按会次归组，散场才出实际交割回执；读信不再次加物品或扣款。遗迹按同一行旅归组，从潮图、外府通关、机缘分取到两层完成逐步留痕；只投递当前里程碑，不追补错过的中间事件。`leads.ts` 复用 seaQuote 显示当前准备/去路，旧信不继续把已取机缘当作待领。两类榜单分别归组，筑基报告列出真实对手姓名，不编造 NPC 自动升榜。

人物问近况新增共享历史回应：分别、接应完成、可靠凝丹确认、约见、现场同行、同行后分别。未知状态仍由驿使回执，不因询问解锁未核验境界。历史 Letter 保持不可变，不把新文案覆盖旧信。

## 世界日程投递接入（2026-11-05）

`calendar.ts` 从 world-evolution 接收实际跨月日程，按既有联系资格投递会讯和人物里程碑；sources 的即时消息仍保留，人物文案统一到 events/companionMessage。重复 ID 不重发，长行动不会仅留下结束时的最新信而漏掉中间经过的里程碑。已过期会讯可能成为闭关期间的旧信，显示原送达年月与当前过期状态；不会自动赴会、改变闭关中断或抽取拍品。

当前日程规则全部可从已有字段确定推导，因此无需新增存档格式。随机世界演化、独立 NPC 资源结算与持久事件账本尚未实施，见世界演化设计。

## 独立人物事实与核验（2026-11-05）

苏婉宁告别后的勘潮为首个持久行动闭环。friendJourney拥有事实发生、玩家得知、核验年月；传讯显示其消息，不用已读推定事实可信。出发/归来转述必须等待本人回信才可核验；本人来信核验能连带确认此前已得知的行程。联系人面板经`supplyFriend`命令寄出灵草2，出发前仅一次；已经启程不追补。详情见 [实施与接手](friend-journey-review/README.md)。
