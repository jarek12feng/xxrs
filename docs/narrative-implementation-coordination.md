# 炼气与筑基剧情接入协作

2026-11-04 用户已授权实施 P1/P2，分派两个独立聊天，并明确同时更新世界地图和旅行路线。本文替代本轮评估中“仅设计、未授权实施”的任务边界；功能完成状态仍须以各批验收为准。金丹新增剧情和元婴不在此次实现范围。

## 所有权

| 负责人 | 范围 |
| --- | --- |
| 炼气聊天 | Q1–Q5；`src/qi-journey/**`、炼气专用开篇组件/投影、必要的 `src/chapter.ts` 开篇文案；炼气专项测试；`docs/narrative-implementation/qi/`；`public/art/world-story/qi/` |
| 筑基聊天 | F1–F6；`src/secret-pact/**`、`src/foundation-journey/**`、筑基专项测试；`docs/narrative-implementation/foundation/`；`public/art/world-story/foundation/` |
| 主聊天 | `src/world.ts`、存档版本/迁移、`src/progression/**`、`src/retreat.ts`、地图与 `src/wayfaring/**`、共用场景路由/互斥、App 与通用测试、统一整合与全量检查 |

两个聊天不提交/推送，不覆盖设计稿或彼此代码。共用文件需要改动时，将精确接口/片段写入自己的 `integration.md`，主聊天执行；不要因共享文件受限放弃领域实现和专用 UI。先在 integration.md 写状态、完成查询、活动/战斗查询、目的地和旅行命令需求，再继续实施。主聊天会读取，不需要互相发送消息。

## 接口与存档

- 炼气新增持久状态优先归 `qiJourney`，复用 qiJourney 命令，不另开世界级剧情巨型对象。
- 筑基新增探府/撤离/追索事实优先归 `secretPact`；利用原 foundationJourney 命令或 secretPact 命令，身份/见闻放明确所属模块。
- 验证器提供旧字段缺失的版本化读取方式或迁移函数，由主聊天统一版本；未知未来存档不覆盖，不为旧档补造经历和奖励。
- 药窟须在凝元前有规则硬校验；照玄须在筑基后期前有规则硬校验，成长上限和闭关预览由主聊天接入。让宝不等于自动过历练。
- 旅行由主聊天统一接距离、成本、出发地、到达命令和续程。各域先给出实际目的地/活动查询，不由界面直接写位置，不新增临时传送。
- 场内观察/走动不扣年月；长途出发显示成本。新地图地标不自动授予线索、资格或任意传送。

## 交付

每个聊天完整实施各自 Q/F 场次并写专项测试、成本对照与使用说明；受共用接口影响的待办写清，不冒充整合通过。素材只复制已完成且检查过的 early 候选到各自允许的运行目录，保留 provenance，不改候选来源。未有角色素材时不借用不相符妖兽冒充具名人族。

主聊天依次整合共用接口、地图旅行、版本/迁移、门槛与互斥，运行 typecheck、专项测试、全量测试、构建及 diff 检查，并执行或明确记录正常 UI 验证边界。已有连续试玩证据不能代替本轮新路线验收。
