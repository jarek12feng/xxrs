## 3. 模块职责与状态最小化

沿用纯 TypeScript 领域命令、统一经济结算、战斗接口及保存成功后呈现。不要把新世界观写成 `world.ts` 的几百个条件分支，也不建立一个包办一切的通用剧情引擎。

- 静态世界信息：新建小型配置模块维护宗门、人物身份、地域和场次 ID；纯事实表不导入 UI。已知信息按实际交谈/观察记录投影，不默认解锁作者秘密。
- 炼气药窟：放入 `qi-journey` 的独立子模块，记录准备、挑战、处置与成果运用；相关凝元校验读取只读完成条件。
- 照玄：复用现有 `secret-pact` 责任与结果，添加探府/撤离完成事实；不要另造一份相互矛盾的贺崇关系。三路入府与新历练门槛由稳定完成查询连接成长模块。
- 有限恩怨：各篇维护自己的触发事实、告知与结局；若两篇确有重复再提炼小接口，不预建全世界仇恨模拟。
- 凝婴：建议独立 `nascent-soul` 域管理圆满考验、准备与叩关，复用经济/战斗/时钟，避免继续堆入 `conclave`。
- 关系与仪式：沿用已定情、已结契事实，明确归属后再迁出跨境界共用状态；仪式进度、大典、宗门身份分开。宾客从人物状态投影，不保存整份重复世界快照。
- 伙伴成长：少量阶段成果和时间记录，不能复制完整玩家系统；年龄、最近消息和事实境界区分。未接完整命运规则前不要批量启用 NPC 寿尽。

每个完成条件须回答：哪些命令能写入、如何校验、重复是否幂等、保存失败保留哪一现场。把“读过提示”和“亲历实战”分别记录，不能用阅读世界观替代硬门槛。

## 4. 新门槛的成本和验证要求

| 改动 | 改前 | 改后设计 | 必须先证明 |
| --- | --- | --- | --- |
| 凝元 | 原路线准备与晋升机缘 | 加必经药窟，实际应用后才可凝元 | 三主修/三路线都能获得入口，无药修强绑；额外耗时不靠劳作循环补齐 |
| 筑基后期 | 取材炼化后继续积累，照玄可不做 | 取材后完成照玄一条实战收束 | 药庄/雪线无需再取一份古道主材；让宝路线有实际考验；不需先后期才能进中期门槛 |
| 凝婴 | 未开放 | 离照、圆满、法门、护神、丹药、灵地和问心 | 资源与余寿足够覆盖有上界的失败恢复；单身/散修仍可达；不把冠军变成必要资格 |

不在本文拍定额外月份、伤害、掉率和价格。每批需给旧/新完整路线总年月、剩余寿元、净资源、挑战次数、有效决策与重复劳动对照；先跑固定种子可达，再做正常 UI 新档连续试玩。必要挑战可难，但不能依赖隐藏随机必败、卡现实时间、一次失误永久失去晋升渠道。

| 批次 | 可独立交付的范围 | 完成标准 |

| P2 筑基照玄与宗门 | F1–F6，三路入府、让宝撤离、条件追索与归山回应 | 分宝各结果有实战与后果；救援顺序不被破坏；单身、散修、三取材路线到圆满回归 |
| P3 现有金丹深化 | G1–G5，问法与外宗关系，补金丹伙伴消息/归山入口 | 现有外海与诸宗会成果不丢，玩家知道凝婴信息来源；不提前展示未开放突破按钮 |
| P4 圆满至元婴闭环 | G6–G8、化婴丹、问心/结契、凝婴、出关及第一段能力兑现，同时交付大典 | 成功与失败补丹都可玩，元婴存读档有效，早婚/新婚/单身/散修大典成立 |
| P5 元婴后续 | 回星墟、道侣机缘、人界秘密与化神/跨界分期 | 每批有自己的成长与收束，不先开长期无解任务；新界域单独验收 |

P1/P2 优先于整卷元婴扩张；用户本次“看看需要怎么修改”不等于本轮已经执行 P1–P5。每批开始前重查并行修改与现行接口，避免覆盖其他模块接入成果。

重点更新现有 `tests/secret-pact.test.ts`、`foundation-growth-mainline.test.ts`、`conclave.test.ts`、`ascension.test.ts`、`cultivation-rules.test.ts`、`save.test.ts` 及相应场景测试；新增用例围绕实质新门槛、失败恢复与知识/人物后果，不写镜像实现的形式测试。
