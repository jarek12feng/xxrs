# 神识与御器重构验收

2026-11-04。本轮由用户授权按评估重构，沿用既有领域模块。规则与前后对照见 [设计契约](../spirit-control-design.md)。这里记录实际实现和证据，不作为商业平衡结论。

## 实施

- 神识上限按境界为 12／24／48，原凝神、队列、丹药、存档校验、拍卖筛选与人物提示使用统一规则。神识不再在筑基后永久停在 12。
- 主器仍一件，辅器改为数组；温养法宝改为明确选择出战。统一容量、单器专御、逐件收回、精炼和器纹规则进入原 `equipment` 接口。原概率关卡与回合伤害的神识贡献封顶 12；多器不新增行动次数。
- 清心丹保留现有来源并按神识阶段递减；金丹养神丹接入原 `medicines`、`workshop`、`economy`、筹备与库存。两类药共用冷却，失败不扣药；库存满时制作不吞资源。
- 外海古渡、会谷安全处允许调整出战器物，但不允许远程拍卖或委托。战斗、秘境、旅行锁保持；主器各入口与辅器／法宝统一显示报价原因。
- UI 显示本境神识上限、御器已用／总量、每器占用、容量不足原因、专御状态、实际服药收益和下一容量门槛。宝物在标准回合战斗与擂台均从统一效果入口结算。
- 存档 v35 校验装备数组与法宝资格，保留 v34 原档首次备份；旧档不赠药、不赠神识，超载旧辅器保留拥有并收回库存，旧温养法宝需自行选择出战。未知未来存档仍拒绝覆盖。

## 自动化证据

新增接口回归覆盖：凝神达到兼御门槛、容量拒绝无副作用、预览与执行一致、重复命令、逐件收回、层级／温养限制、药力递减与共用冷却、满境停止与越境拒绝、丹药原子收支、伪造和重复装备拒绝、v34 首次备份、旧档超载收回、战斗／旅行／事件禁用、真实 Vue 按钮的容量提示和双辅器。

历史迁移测试改用真实旧装备格式，不把当前数组结构只改版本号当旧档。纯战斗引擎继续通过旧数值指纹：原来自动温养的输入由该测试显式提供，新的出战效果由独立规则测试覆盖。

首轮全量 1022 项中 985 通过、37 失败，主要为版本断言、历史存档夹具和自动温养的旧预期；定向检查还发现外海／会场把所有宝物命令一并拦截，已只放行安全处装备操作。第二轮 1045 项中 1044 通过，剩余旧 v32 夹具用了新上限神识 18，已改为旧格式允许的数值。未通过放宽旧档校验解决。

独立复核前 `npm test -- --maxWorkers=2`：147 个文件、1046 项全部通过，59.14 秒。`npm run build`（含严格类型检查）与 `git diff --check` 通过。主包 986.11 kB、Phaser 分块 1220.07 kB，仍有超过 500 kB 的既有体积提示，本轮未宣称解决包体问题。

## 现有剧情路线

- [外海 12 条固定种子命令路线](sea/routes.json)：三主修 × 两种潮图选择 × 两种首取宝物；通过两层遗迹。拿镇潮印的路线先凝神至 18、温养，再明确出战。
- [诸宗会 24 条固定种子命令路线](conclave/routes.json)：三主修、两条秘境路、两种整备、两种转修组合；诸宗会两胜、定神珠、归潮深处与金丹后期打通。定神珠温养后凝神至 36，再出战；已有主器和镇潮印保留。
- 各目录的 `start.json`／`completed.json` 是由公开命令生成的合成审计存档，用于重放核查，不是实际玩家连续试玩档。旧审计目录未覆盖。

复现：

```sh
npx esbuild tools/outer-sea-audit.ts --bundle --platform=node --format=esm --outfile=/tmp/xxrs-spirit-sea.mjs
node /tmp/xxrs-spirit-sea.mjs docs/spirit-control-review/sea
npx esbuild tools/conclave-audit.ts --bundle --platform=node --format=esm --outfile=/tmp/xxrs-spirit-conclave.mjs
node /tmp/xxrs-spirit-conclave.mjs docs/spirit-control-review/conclave
```

这些路线证明给定准备与操作下可达，不是胜率、所有装备组合、时长或玩家留存证明。

## 独立复核与修复

独立会话只读复核发现两处确定入口缺陷，现已修复：外海／会谷主器加工绕过地点限制；凝丹取药 prepared／path／won 阶段装备报价与执行不一致。主辅器共用地点限制，装备共用取药阶段锁；安全处换装保持可用。

另外处理三项体验观察：清心丹神识 12–23 的炉房报价明确提示凝神一月同增 1、无需材料，保留现成药品省时用途；装配辅器／法宝前显示正确应对时各招式相对当前的伤害和承伤净变化，计入专御损失（实际战果仍受境界压制、承伤下限与击倒免反击影响）；旧档已温养法宝收回时写入日志和宝物提示，明确自动加成已停止。低血量旧外海战档已通过迁移、撤退、收回主器、重新出战镇潮印的命令回归。

修复后独立复查通过：两处确定缺陷消除，未发现新阻塞；独立重跑 3 文件 52 项通过。主会话最终全量 `npm test -- --maxWorkers=2` 为 147 文件、1051 项通过（59.01 秒）；随后仅补全预览边界文案，宝物 UI 3 项与 `npm run build` 再次通过。`git diff --check` 通过；主包 987.57 kB，既有体积警告仍保留。外海 12 条及诸宗会 24 条路线重新通过。

独立复核未发现重复法宝基础收益、交替服药绕冷却、主器互换重复占用或重复装备收益。参数未据此宣称全面平衡，仍需代表性敌人与真人构筑体验验收。
